# 虚拟文件夹（v0.18）

## 需求与交互

延续 One 的文件列表和“格式与信息”窗口，让用户复制邮件或其他 OLE 来源中的目录后，保留相对层级、文件内容和空目录。来源退出后仍可搜索、加入堆栈、保存为模板、复制/粘贴、拖出及备份恢复。只保存来源实际枚举的成员，不主动扫描来源磁盘或调用 Shell 执行对象。

详情显示相对路径并区分“已保存文件夹”和普通附件。“格式与信息”允许单独另存文件或整棵子目录；内部信息只列可读取的文件。复制和拖出只提供顶层项目，避免同一子文件重复出现在目标中。原描述时间和属性继续保存；不据属性创建链接、只读或隐藏对象。

## 数据与兼容

沿用 attachments 数组，name 扩展为反斜杠分隔的相对路径。文件维持原有字段；目录明确记录 directory: true，data 必须为空字符串，区分零字节文件与空目录。平面附件的规范化结果保持不变，避免已有内容哈希改变。

整组最多 256 个节点（含目录及补建的缺失父目录）、16 层、相对路径最多 259 个 UTF-16 单元，每段最多 255。补建父目录只源于已枚举子项，不获取额外内容。允许描述乱序，但保留原始列表索引读取 FileContents；目录绝不请求文件内容。全部名称、层级和容量检查通过后才保存整组，任一文件读取失败不保存残缺目录。

拒绝绝对/UNC/设备路径、正斜杠、空段、点段、ADS、保留名、尾点/空格、重解析点、设备属性、大小写重名、父子名称大小写冲突和文件作为父目录。目录若声明非零文件内容则拒绝。原始总内容仍不超过 12 MiB，单条/总历史预算和读取进程资源限制沿用已有约束。

数据库与普通备份提升为版本 6；旧版拒绝新库。继续导入 1–5 版备份，但这些版本不允许目录或层级附件，避免把新数据伪装成旧格式。原有平面附件、模板、标签、隐私标记不改写。局域网同步和网页共享仍不传输文件或目录，同步协议保持版本 4。

## 文件生成与生命周期

复制/拖出先在专用随机缓存组内创建完整树，逐段检查目录及物理路径，不跟随链接；文件用独占新建和文件句柄写入，最后返回顶层路径。检查会话有效性，取消/锁定/迁移后不发布结果；失败删除本次生成组。目录时间在子项写完后设置。缓存递归计量仍有节点/深度限制，无法检查或清理的组保守占用额度，链接只移除链接本身。

另存目录让用户选择一个新目录名称，先在同一父目录的随机暂存目录写完整子树，再以不替换目标的 Windows 移动操作提交。已有文件或文件夹整组拒绝，不合并、不覆盖；目标资料目录沿用已有保护。只清理本次创建且身份未改变的暂存目录，不对用户选中的已有目标递归删除。另存输出为未加密内容，不自动打开。

## 验收

逻辑与真实数据库：平面兼容、层级/隐式父目录、空目录、大小写/路径冲突、节点/深度/容量、错误版本拒绝、模板与加密恢复、缓存取消和链接替换、目录导出冲突保留。

真实 OLE：W/A 描述，目录前后及乱序列表、空目录、不为目录请求内容、子文件原始索引、HGLOBAL/IStream/IStorage 混合、源退出后复制、实际文件拖出和保存子树、锁定/迁移/退出清理。受控样本通过不等于 Outlook 等全部真实应用兼容；物理应用验证单独记录。

## 依据

[Shell Clipboard Formats](https://learn.microsoft.com/en-us/windows/win32/shell/clipboard) 规定描述与文件内容索引的关联；[FILEDESCRIPTORW](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/ns-shlobj_core-filedescriptorw) 说明有效字段与名称结构；[MoveFileExW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw) 支持同卷目录及其子项移动。本项目的树结构校验、额度与界面是独立设计，未据文档推断所有来源应用都枚举完整目录。

当前状态：实现完成，155 项逻辑测试与同一发布包 41 组桌面套件通过；具体证据与限制见《验收-0.18》。
