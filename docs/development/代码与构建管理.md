# 代码、开发与存储规则

代码在 `D:\Repositories\Clipper` 开发，通过私有 Git 仓库 `Robert-Stackflow/Clipper` 管理。提交和标签记录代码版本，不创建小版本源码副本。此前 D 盘 0.19 源码已保存在本地 `archive/local-0.19` 分支。

目录分工参考 `D:\Repositories\One`：应用源码在 `src`，原生实现放根目录 `native`，静态资源放 `assets`，流程放 `scripts`，验证放 `tests`。Clipper 的安装器源码额外放在 `build/installer-ui`，NSIS 配置放在 `build`。

## 开发流程

双击根目录 `Start-Clipper-Dev.cmd` 或运行 `npm run dev`。生产构建和开发监听共用构建配置；只编译变更部分，界面自动刷新，主进程和预加载变更后正常退出并重启。C#、C++、Rust 或构建配置改变后重新运行开发命令。

连续构建触发重启时，启动器对同一个 Electron 子进程只发送一次退出请求；退出超过 15 秒会记录提示。若用户在未保存内容确认框中取消退出，下次修改主进程时可以重新请求。隔离的开发热更新检查覆盖界面刷新、主进程与预加载重启以及私有资料保留。

开发资料固定在 `work/dev-profile`，与日常程序资料分开；自动记录默认开启。0.50.0 对旧开发资料只执行一次开启迁移，之后保留手动暂停；划词菜单及其原生进程已移除。隔离测试主动暂停自己创建的资料。开发命令只管理自己启动的 Electron。未保存的捕获、录制或图片编辑会暂缓界面刷新。

## 目录职责与保留

| 目录 | 规则 |
| --- | --- |
| `dist` | 当前编译结果，覆盖复用；过期文本预览资源随构建清理 |
| `build` | 安装器源码与配置，受 Git 管理，需要保留 |
| `release` | 完整可运行版本，只保留最新两个 |
| `release/.building` | 单个带标记的发布暂存目录，失败或结束后清理 |
| `work/dev-profile` | 一个持续复用的开发配置 |
| `work/development` | 开发刷新回归的固定隔离配置与结果 |
| `work/current` | 固定测试目录；新工作流最多保留 20 组、128 MiB 的报告与截图 |
| `work/current/<检查>/fixtures` | 本次私有样本，检查结束后删除 |
| `work/document-info-build` | 唯一一份 Rust 编译缓存 |
| `work/temp` | 当前构建和验证的临时目录 |
| `verification` | 固定位置的管理报告，不存源码或程序副本 |
| `node_modules` | 一份当前依赖，不按版本复制 |

`npm test` 的临时样本由固定工作区管理；`npm run verify -- <名称>` 用于已支持该入口的界面检查。旧的检查脚本逐步迁入该入口；需要键鼠、剪贴板或安装的检查继续单独执行，不能直接套用自动界面验证。

`npm run package` 从当前 Git 工作目录构建。先核对旧程序没有被占用，在固定暂存目录生成候选包，核对 EXE、版本及全部编译文件后移动到版本目录，再淘汰超过两版的程序。构建一致性报告不等于全部功能验收。

源码、文档、测试固定样本和许可提交 Git。`dist`、`work`、`release`、`verification`、`node_modules` 和本机环境文件被忽略。用户资料、主动导出的文件与备份不属于开发缓存。

## 现有冗余清理

`scripts/clean-generated.ps1` 默认只列出目标。人工检查后增加 `-Apply` 执行，增加 `-Caches` 包含旧测试临时目录。

脚本核对绝对路径、Git 保存状态、进程占用和目录链接；保留源码、当前依赖、开发配置与 Rust 缓存。自动删除此前被审批拦截的退役目录尚未执行，需手动运行脚本。新工作流只自动清理自己带标记的生成文件，不接管旧的无标记目录。
