# 代码、开发与存储规则

在当前仓库根目录开发，通过私有 Git 仓库 `Robert-Stackflow/Clip` 管理。提交和标签记录代码版本，不创建小版本源码副本。此前 0.19 源码已保存在本地 `archive/local-0.19` 分支。

目录分工沿用 One 的分层：应用源码在 `src`，原生实现放根目录 `native`，静态资源放 `assets`，流程放 `scripts`，验证放 `tests`。安装器界面和主进程放在 `installer`，NSIS 配置放在 `build`。入口与功能定位见 [源码导航](../../src/README.md)。

## 开发流程

双击根目录 `Start-Clip-Dev.cmd` 或运行 `npm run dev`。生产构建和开发监听共用构建配置；只编译变更部分，界面自动刷新，主进程和预加载变更后正常退出并重启。C#、C++、Rust 或构建配置改变后重新运行开发命令。

连续构建触发重启时，启动器对同一个 Electron 子进程只发送一次退出请求；退出超过 15 秒会记录提示。若用户在未保存内容确认框中取消退出，下次修改主进程时可以重新请求。隔离的开发热更新检查覆盖界面刷新、主进程与预加载重启以及私有资料保留。

开发资料固定在 `work/Clip/dev-profile`，与日常程序资料分开；自动记录默认开启，手动暂停状态会保存。正式资料默认使用 `%APPDATA%\Clip`，会话、日志及崩溃记录写入所属资料目录；安装器会话使用 `%APPDATA%\Clip\installer`。不读取旧应用或旧开发目录，不执行旧数据迁移。划词菜单及其原生进程已移除。隔离测试主动暂停自己创建的资料。开发命令只管理自己启动的 Electron；截图、录制及图片编辑不再属于 Clip 的开发刷新流程。

## 目录职责与保留

| 目录 | 规则 |
| --- | --- |
| `dist` | 当前编译结果，覆盖复用；过期文本预览资源随构建清理；保留主进程构建实际生成的 `index.cjs.map` |
| `build`、`installer` | NSIS 安装引擎配置与 Electron 图形安装器源码，受 Git 管理，需要保留 |
| `release` | 完整可运行版本，只保留最新两个 |
| `release/.building` | 单个带标记的发布暂存目录，失败或结束后清理 |
| `work/Clip/dev-profile` | 一个持续复用的开发配置 |
| `work/Clip/development` | 开发刷新回归的固定隔离配置与结果 |
| `work/Clip/current` | 固定测试目录；新工作流最多保留 20 组、128 MiB 的报告与截图 |
| `work/Clip/current/<检查>/fixtures` | 本次私有样本，检查结束后删除 |
| `work/document-info-build` | 唯一一份 Rust 编译缓存 |
| `work/Clip/legacy-test-profiles` | 经来源核对的旧测试配置集中归档，原路径与归档清单见 `verification/storage/repository-tidy-2026-10-10.json`；归档不释放磁盘空间 |
| `work/Clip/temp` | 当前构建和验证的临时目录 |
| `verification` | 固定位置的管理报告，不存源码或程序副本 |
| `node_modules` | 一份当前依赖，不按版本复制 |

`npm test` 的临时样本由固定工作区管理；`npm run verify -- <名称>` 用于已支持该入口的界面检查。旧的检查脚本逐步迁入该入口；需要键鼠、剪贴板或安装的检查继续单独执行，不能直接套用自动界面验证。

## 脚本与验证入口

| 入口 | 职责 |
| --- | --- |
| `scripts/dev.mjs`、`bundle-options.mjs` | 开发监听、窗口刷新与正常重启；共享编译入口 |
| `scripts/build.mjs`、`build-*.mjs` | 桌面/网页编译、原生辅助程序及安装器构建 |
| `scripts/test.mjs`、`tests/*.cjs` | 核心逻辑回归及按功能命名的界面/系统检查；固定样本在 `tests/fixtures` |
| `scripts/verify.mjs`、`workspace.mjs` | 支持的隔离界面检查、生成标记、样本清理与证据容量限制 |
| `scripts/package.mjs`、`release.mjs`、`verify-packaged.mjs` | 目录包、发布暂存与版本/文件一致性校验 |
| `scripts/check-language*.mjs`、`notices.mjs`、`rust-notices.mjs` | 语言静态校验与第三方许可维护 |
| `scripts/clean-generated.ps1` | 有边界的生成物清理预览与执行 |

完整命令以根 `package.json` 为准。测试脚本保持现有路径，避免破坏命令、构建和工具间引用；只在存在职责冲突时迁移模块。新临时脚本、日志和输入样本放到所属 `work/Clip/current/<任务>`，不散落到项目根或源码目录。

`npm run package` 从当前 Git 工作目录构建。先核对旧程序没有被占用，在固定暂存目录生成候选包，核对 EXE、版本及全部编译文件后移动到版本目录，再淘汰超过两版的程序。构建一致性报告不等于全部功能验收。

源码、文档、测试固定样本和许可提交 Git。`dist`、`work`、`release`、`verification`、`node_modules` 和本机环境文件被忽略。用户资料、主动导出的文件与备份不属于开发缓存。

## 现有冗余清理

`scripts/clean-generated.ps1` 默认只列出目标。人工检查后增加 `-Apply` 执行，增加 `-Caches` 包含旧测试临时目录。

脚本限定在本机 `D:\Repositories\Clip` 的 Git 仓库内，核对绝对路径、进程占用和目录链接；保留源码、当前依赖、开发配置与 Rust 缓存。主进程构建配置启用 sourcemap，`dist/main/index.cjs.map` 属于当前输出，不能按旧清单删除。

`-Caches` 会扩展到旧测试缓存，须先关闭开发及验证进程并预览计划。新工作流只自动清理自己带标记的生成文件，不接管旧的无标记目录。手动整理旧工作数据时，只有核对测试创建代码、严格目录前缀和随机后缀、无活动进程/标记后，才能回收可再生的 profile；保留同目录的文字报告、截图和复现证据。旧开发 profile 可能含历史与账户资料，不能因路径过时或被 Git 忽略就删除。
