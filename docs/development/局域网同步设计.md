# 局域网同步设计

对应 OneClip 的多设备文字/图片同步能力，采用 Clipper 独立协议，不假定与 OneClip 商业版本互通。依据 [OneClip 功能说明](https://github.com/One-Clip/OneClip)、[Node TLS](https://nodejs.org/api/tls.html)、[X.509 生成库](https://github.com/PeculiarVentures/x509)。

## 用户流程与隐私

默认关闭网络监听与发现。启用后可查看附近 Clipper，也可把五分钟有效、单次使用的配对码交给另一设备。配对码包含服务器证书指纹和随机凭证；接收方先核对证书，双方确认后保存信任。配对设备只能访问共享记录，不能读取其他历史、模板、脚本、设置、密钥或任意文件。私钥使用 Windows DPAPI 保存。

已有历史不自动发送。用户可主动共享单条文字/图片，或启用“自动同步新复制内容”。0.27 起支持文件/附件副本：仅在主动共享或开启自动共享文件时读取原件，原路径不发送；每组最多 12 MiB、256 项、16 层，另受 Base64 编码后的单条容量限制。接收到的内容仅加入历史，不回写系统剪贴板或触发粘贴。把一条内容设为“仅本机”会撤回已共享副本，并阻止该内容再次自动分享；其他设备再次发布相同内容也会被撤回。已送达其他设备的资料无法保证从其备份中消失。配对码被复制时自动标为仅本机。

## 网络与设备

TLS 1.3，双向证书呈示与精确 SHA-256 指纹校验；初始配对仅限显式打开的窗口。关闭同步立即关闭监听、发现和活动连接；撤销设备信任立即阻止后续请求，已经接收的本机副本保留。IPv4 私网地址与链路本地地址；不接受域名、公网地址、跳转或代理。回环地址只用于同机验证。

附近发现通过 TTL=1 的 UDP 多播，只广播设备名称、身份、端口和公开指纹，不含剪贴板或配对凭证。发现结果不能授予信任；连接始终检查已保存指纹。应用不自动修改防火墙规则。

## 内容与删除

每次发布有独立 UUID，记录正文不可变。接收时按内容哈希合并本地重复项；收藏、置顶、标签和模板仍由本机管理。与已有本机内容重复时，标记该本机原件的保留权，远端撤回不会删除它；用户主动发布该条后才遵守完整共享删除规则。同步目录只映射共享记录，不复制全部正文。

编辑共享文字会删除旧发布并创建新发布。不同设备离线编辑产生两个新发布，两个结果都保留；删除标记优先于同一发布的任何旧副本，重试不能使旧发布复活。主动重新共享或再次复制已删除内容会创建新的发布身份。删除本地记录传播到其所有已知发布；自动清理不删除共享记录。停止分享保留本机内容，同时传播删除标记。

删除标记不按时间偷偷回收，以免离线设备复活旧数据。同步目录设 20,000 条上限；达到上限时停止新增并显示错误，后续实现显式重建同步网络流程。单条内容遵守现有 16 MiB、文字 1 MiB 及总历史 256 MiB 上限。网络按单条事务处理，失败不留下半条记录；重试幂等。

## 实施与验收

新增同步核心、TLS 传输、发现、配对服务和独立界面。对正常记录保存/删除建立事务内通知；同步使用已有串行写队列，网络等待不占用采集队列。迁移时停止连接并切换存储，备份不包含设备身份或信任信息。启动恢复副本清除同步身份、信任关系、目录与共享标记，默认关闭同步，使用者需重新配对。

验收包含两个隔离资料的真实 TLS 配对、未授权请求拒绝、证书不匹配时不发送正文、文字/图片双向与多跳同步、离线编辑冲突、删除重放、容量失败回滚、撤销/关闭、重启、发现和 UI 操作。单机双进程验证不能替代两台物理设备、防火墙和路由器兼容性验收。网页实时分享已作为独立临时会话实现，浏览器访客仅支持文字与 PNG。

## 0.46.6 发送大内容

通过已有轻量摘要判断正文大小；超过 64 KiB 的共享内容使用最多两个短期工作线程读取只读 SQLite 快照。准备至传输完成最多占用两个正文槽位，慢连接不能堆积已编码的大正文。加密资料使用独立密钥副本，移交后清零。工作线程直接提取数据库中的正文 JSON、编码进可转移的专属字节数组，避免再次解析和序列化大 Base64 字符串。没有新增协议版本、数据库格式或临时明文文件。

发送前按当前资料、同步代次、发布身份、内容哈希和共享状态重新检查；推送在证书精确匹配后再检查，才释放 HTTP 请求。撤销/关闭取消工作线程与连接，传输完成或失败后清除准备的字节。短文本保留即时处理，旧协议筛选读取轻量格式摘要。参考 [Node 工作线程的数据转移说明](https://nodejs.org/api/worker_threads.html)，未引入新的第三方依赖。

接收后的 JSON 解析、内容校验和写入，以及文件发布的最终落库仍需优化。本轮只对发送准备做隔离测量与 TLS 文件数据库回归，详见 [0.46.6 验收](../history/验收-0.46.6.md)。

## 0.46.7 接收大内容

独立网络缓冲区超过 64 KiB 时直接移交短期工作线程；从读取正文至提交完成最多占用两个接收槽位。准备完成后进入既有串行写队列，由工作线程在 SQLite 写事务中校验并保存，同时更新共享目录和派生缓存。完整正文留在线程中，通知只包含记录身份及隐私字段。原始内容与共享标记合并为一次保存，重复项仍保留本机收藏、置顶、标签及保留权，仅本机内容产生撤回标记。

共享取消标记在提交决定前阻止写入；已作出提交决定时，停止等待事务完成，避免中途终止已接受的提交。配对状态确认和取消写入信任设置时也经过同一串行队列。关闭、撤销、资料锁定/切换使尚未提交的任务失效，连接与线程退出后释放槽位和密钥副本。删除仍在拥有撤销快照的主连接处理；PNG 原生缩略图生成仍使用现有主进程解码器。未改协议版本和数据库格式，也未引入明文生产暂存。

10 组新增核心回归、真实 TLS 文件数据库、包内加密写入和五轮固定基线对照见 [0.46.7 验收](../history/验收-0.46.7.md)。正文获取以外的接收耗时已测量，尚不能代表真实双机端到端体验或长期驻留内存。

## 0.46.8 文件发布与 PNG 缩略图

文件发布队列只保存记录身份，最多四个任务、一个活动线程。线程从本机数据库取得文件路径，沿用锁定读取与容量检查，准备完后才进入主进程串行写队列。线程在原子事务内复核原件身份及仅本机状态，保存副本、共享标记和目录；主进程只收到轻量变更通知。准备阶段不占写队列，最终提交仍阻止其他写入，不能把主进程响应提升理解为所有写操作即时完成。取消在接受提交前回滚，接受后停止等待提交和线程退场；密钥副本清零。

PNG 缩略图通过 WIC 原生短期进程生成，PNG 字节分块输入，不落明文暂存。一个活动解码器、最多四个任务、64 MiB 编码引用上限、384 MiB 子进程上限、15 秒超时；输出不超过 280×180 和 1 MiB。原件与输出均校验，透明度保留。工作完成才进入后续保存队列，停止等待进程退出。JPEG 等转换和备份恢复仍有原同步解码路径。

明文/加密数据库回归、固定基线和连续操作范围见 [0.46.8 验收](../history/验收-0.46.8.md)。协议和数据库格式未变。
