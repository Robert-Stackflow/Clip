# Clip 架构与设计

更新：2026-10-10 · 基线：0.51.2。本文描述当前分层与主要调用链；模块定位见 [源码导航](../../src/README.md)，历史版本设计见 [设计分期](../history/projects/设计分期-0.1至0.50.0.md)。

## 界面与进程

主窗口包含历史、收藏、堆栈、拖拽容器、快捷回复、自定义分类、工具和设置。最近记录、快捷面板、预览、托盘菜单、AI 对话及解锁/恢复使用各自窗口与受限预加载入口。截图、录制、图片编辑、贴图和划词窗口已移除。

界面沿用 One 的原生 DOM/CSS、线性图标、浅深主题、共享控件与动效；列表、卡片和详情优先复用已有渲染组件。字体、密度、中英文与减少动态效果使用共享设置，页面只呈现已实现功能。专项规范见 [字号与紧凑布局](字号与紧凑布局设计.md)、[中英界面](中英界面设计.md) 和 [One 组件来源](../research/ONE-UI-MIGRATION.md)。

## 模块职责

| 层 | 职责与入口 |
| --- | --- |
| `src/main` | Electron 生命周期、窗口、IPC、剪贴板、存储、后台任务和系统集成；入口 `index.ts` |
| `src/preload` | 各窗口的 contextBridge 与 IPC 接口，避免将通用 Node 能力暴露给页面 |
| `src/renderer` | 原生 DOM/TypeScript/CSS 页面；主入口 `app.ts`，窗口页面和资源由构建入口选择 |
| `src/shared` | 类型、参数校验、纯逻辑、预览协议与中英语言目录 |
| `src/web` | 网页共享访问端，与桌面页面入口分开 |
| `native` | Windows 原生辅助程序与 Rust 文档信息读取器 |
| `installer`、`build` | 图形安装器源码与 NSIS 配置；均属于源码 |

依赖版本以 `package.json` 和锁文件为准，编译入口在 `scripts/build.mjs`。生成文件写入 `dist`，不得放回源码目录。

## 主要调用链

- 剪贴板变化 → `clipboard.ts` / `native.ts` → 校验与去重 → `capture-writer.ts` / worker → `store.ts` → 列表索引、预览及窗口刷新。系统剪贴板采集与 Frame 的屏幕捕获分属不同功能。
- 页面操作 → 对应 preload → `index.ts` 中的 IPC 处理与参数/来源校验 → 服务或 Store → 有限结果。复制/粘贴检查原窗口身份和焦点，避免错误回贴与误消费队列。
- 历史列表与最近记录 → 列表/预览索引、`tray-query.ts` / worker → 摘要展示 → 需要时读取正文和图片。大内容转换、元数据与同步附件按已有 worker 边界处理。
- 备份/恢复 → 后台任务与 worker → 校验、预览及事务提交；同步 → 配对身份/TLS → 消息与附件校验 → 账本及 Store。
- AI/对话 → `ai.ts` / `chat.ts` → 传输适配；Codex 由 `codex-runtime.ts` 定位本机程序，`codex-provider.ts` 管理独立账户连接。脚本通过独立 worker 和 QuickJS 执行。

## 数据与安全边界

`store.ts` 管理记录、快捷回复、分类、堆栈等数据及索引。普通历史通过 `database.ts` 使用 Node SQLite；加密历史使用 `better-sqlite3-multiple-ciphers`，密钥通过原生 buffer 接口传递。加密/锁定与恢复由 `history-vault.ts` 等模块协调，不将加密描述成完整隐私保证。

Electron 页面使用 sandbox/contextIsolation，关闭 nodeIntegration；固定预加载与资源协议，限制导航、窗口和权限请求。IPC 与导入数据校验边界、类型和容量；外部富文本按安全表示处理，不能执行附带脚本。原生句柄由主进程管理。

正式资料、独立开发资料、测试 profile 和发布产物分别管理。用户导出与备份不属于开发缓存；现行路径、生成物清理及构建流程见 [代码与构建管理](代码与构建管理.md)。具体协议与验收条件见 [专项规格索引](../README.md#专项规格)。
