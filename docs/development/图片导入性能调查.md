# JPEG 导入阻塞与原生转换兼容性

调查基线版本 0.49.8（b9c63d1）的 `incomingFiles` 在主进程解码 JPEG、GIF、BMP、WebP 并编码 PNG，再向已有独立缩略图进程发送 PNG。PNG 缩略图与局域网共享最终保存已有后台实现，不应重复把这两项当作未迁移路径。

本文保留 0.49.8 阶段的导入测量与 JPEG 解码兼容性调查。当时正式程序未切换解码器；后续 CMYK 修正、正式后台转换及完整导入测量见 [0.49.9 验收记录](../history/验收-0.49.9.md)。已经验收的肤色选择顶部间距不再调整，录音录屏性能继续排除。

## 实际导入路径测量

固定提交的 transfer.ts 与生产缩略图服务；真实 Electron 无窗口进程，分别读取 8,000 × 4,800 的纯色 JPEG 和 1,600 × 1,600 的确定性噪点 JPEG。资料在独立生成进程创建，每种资料各三轮，旧路径与 WIC 全尺寸 PNG 转换原型交替运行，合计 12 个独立主进程。

导入包含文件读取、验证、原格式保留和独立 PNG 缩略图完成，不包含数据库保存、剪贴板、拖放或可见界面。因此下面的计时器间隔证明主进程阻塞，不直接证明桌面交互延迟。原文件及原格式字节使用 SHA-256 核对，所有任务结束后无活动缩略图进程。

| 中位数 | 大图旧路径→原型 | 噪点旧路径→原型 |
| --- | --- | --- |
| 导入时间 | 386.5→692.9 ms | 354.0→442.6 ms |
| 主进程最大计时器间隔 | 296.3→24.6 ms | 237.4→62.2 ms |
| 主进程 Windows 峰值工作集 | 254.8→107.9 MiB | 164.6→161.2 MiB |
| 主进程与解码辅助进程峰值之和上界 | 263.9→118.3 MiB | 186.5→188.3 MiB |

大图旧路径第一轮间隔 1,070.3 ms，原型第一轮 90.9 ms，均保留；其他大图旧路径 285.4–296.3 ms，原型 16.6–24.6 ms。没有重跑来替换慢轮次。原型改善主进程响应，但导入总时间明显更长，噪点峰值上界略高，不能声称所有场景更快或总峰值稳定降低。

Windows 主进程与辅助进程峰值分别读取，二者之和是保守上界，不能当作同时发生的全应用峰值。父进程峰值包括启动与返回内容的字节核对。记录不存在界面或长期驻留验收。

完整样本：[image-import-performance-0498.json](../history/measurements/image-import-performance-0498.json)。运行 `node tests/image-import-performance.cjs`；原型只在测试资料目录编译，完成后删除生成资料，保留报告。

## 解码兼容性与决定

用 Pillow 10.4.0 生成 13 种 JPEG，包括 RGB、灰度、渐进编码、CMYK、嵌入 sRGB ICC、EXIF 方向 1–8。真实 Electron 原解码器与 WIC 原型逐像素核对尺寸及 BGRA 字节，不以 PNG 压缩结果不同来判断图像是否相同。损坏 JPEG 拒绝，原文件字节不变。

12 个 RGB/灰度样本完全一致，包括方向标签样本；这只证明原有方向行为得以保留，不表示程序新增了方向自动校正。CMYK 样本虽然尺寸相同，却有 9,082 个通道值不同，最大差值 90，平均差值约 20.21。WIC 原型因此不满足颜色兼容性，暂不接入生产代码；不能用正常 RGB 样本替代对 CMYK 的要求。

完整样本：[image-import-codecs-0498.json](../history/measurements/image-import-codecs-0498.json)。运行 `node tests/image-import-codecs.cjs`；需要可用 Python/Pillow，可通过 `CLIPPER_TEST_PYTHON` 指定解释器。初次调查依赖前一测量已清理的临时模块，未能运行；已改为每个调查独立创建原型，后续 13 个样本完整记录。未修改生产行为来适配测试。

下一步应验证与原解码器颜色一致的后台转换方案，并覆盖其他现有格式、取消和锁定、任务退役及真实操作流程。当前数据不能支持把 JPEG 后台转换、全应用峰值或长期驻留标为完成。本轮仅新增调查及报告，因此不重复无关的整套核心回归或已经验收的 UI 检查。
