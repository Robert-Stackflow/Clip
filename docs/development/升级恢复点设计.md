# 升级恢复点与版本回退

完整目标包括升级前数据留存、异常启动恢复、数据回退、程序版本回退和旧格式兼容核对。安装失败时恢复程序文件已有实现；这不代表历史数据格式回退已完成。本阶段实现完整数据恢复链路，程序版本回退仍保留后续范围。

首次打开不同版本的已有资料时，在迁移、清理或修改设置前创建完整恢复点。恢复点保留原数据库格式及全部 SQLite 表、索引和触发器，包含 WAL 中已提交内容；加密数据库保持加密并同时保留原密码/恢复密钥封装。只在校验和写入成功后打开资料。新资料不生成空恢复点，同版本重启不重复生成。

恢复点位于默认资料目录的 `history-checkpoints`，每个随机编号目录包含数据库、必要的加密配置及版本、时间、资料编号、容量和摘要清单。数据库复制与校验在有界工作线程进行；未完成目录不会进入列表。数据页提供手动创建、内容预览、复制恢复和删除；启动恢复页可直接选择已有恢复点。恢复点含完整本机数据库配置，与不包含 API 密钥的 JSON 备份用途不同，不应公开分享。

恢复创建独立目录并原子切换，当前资料与原恢复点均保留。恢复后暂停记录、自动备份和同步，避免旧同步状态对其他设备产生影响。加密恢复点用原密码或恢复密钥解锁；在当前资料要求加密时，从明文恢复点恢复必须设置新密码并确认新恢复密钥，不落地明文临时数据库。

默认合计保留最近三份版本变化和安装更新前的自动恢复点；手动恢复点由用户自行删除。保留规则只删除摘要校验通过且属于当前资料的本应用恢复点。界面明确标记明文恢复点；开启历史加密不会追溯加密它们。删除需用户在应用中确认，并只清理已验证的固定文件。

旧程序可通过其恢复向导连接相应恢复点目录。恢复点从未被新版写入，原格式仍可由匹配版本读取。安装器目前拒绝降级；完整程序版本回退尚需配套保留旧程序、旧注册及数据事务，不能把数据恢复或安装失败恢复标记为该目标完成。

验收覆盖旧格式、全部数据与配置、WAL、加密原格式、失败不改原目录、版本重启去重、列表与删除边界、校验后改变、启动失败与未来格式、加密保护、完整复制恢复和大历史后台处理。全部使用隔离资料与窗口。
