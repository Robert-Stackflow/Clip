# 存储迁移、备份与恢复设计

这是阶段 4 的第一批实现，发布为 v0.4；局域网同步、数据库加密与 Windows Hello 仍属于该阶段的后续范围。本次以现有 SQLite 历史结构为基础，保持 One 的页面风格和 main / preload / renderer 边界。

## 自定义数据目录

默认位置仍是 `%APPDATA%\Clip`。新增 `storage-location.json` 保存版本、资料身份、当前目录和上次目录；Electron 用户目录和缓存留在默认位置，只有历史数据库迁移。这样单实例锁、系统安全存储和协议注册仍使用同一应用身份。

用户选择普通本机空文件夹并确认迁移。主进程串行队列暂时冻结数据写入，结束正在运行的 AI 与脚本，使用 SQLite `VACUUM INTO` 生成一致副本。对副本执行完整性检查、资料身份校验和三个表的有序 SHA-256 内容对比，再以禁止覆盖方式生成目标数据库并同步到磁盘。目标数据库可打开后，原子替换位置配置，切换所有服务，最后关闭原连接。切换前失败保留原位置，清理本次已创建文件；不递归删除目录或覆盖已有目标内容。

原目录不会自动删除，迁移后的新记录只写入新目录。临时拖出图片与缓存仍在默认目录，文件历史引用的源文件不搬动。目录不可用、身份不符或配置损坏时进入 v0.4.1 专用恢复窗口，不静默创建空历史。正常打开已有数据库前也先只读校验；校验失败不会运行迁移或保留策略。

迁移依据：[SQLite VACUUM INTO 文档](https://www.sqlite.org/lang_vacuum.html)。迁移快照与位置配置的提交顺序有自动化失败测试，但未模拟真实断电或磁盘硬件故障。

## 备份格式与加密

明文 JSON 备份升级为 `clip-backup` version 3：历史、富模板、分类、文本脚本。兼容导入 v1 / v2，不导出 API 密钥、服务配置、自动备份密码、系统设置、堆栈/容器顺序和源文件本体。恢复按内容合并，不覆盖本机配置；脚本只导入，不执行。脚本容量超限会和其他内容一起回滚。

可选 `.clip` 加密容器采用 Node 内置 AES-256-GCM：固定格式标识及版本、16 字节随机盐、12 字节随机 IV、密文、16 字节认证标签。头部参与 AAD 校验；每次导出使用新盐和 IV。密码经 scrypt 派生 32 字节密钥，固定 N=32768、r=8、p=1，不接受文件提供的 KDF 参数。派生内存限制 64 MiB；输入文件上限 384 MiB，不压缩，避免解压炸弹。密码需 12–1024 字符。

自动备份密码通过 Windows DPAPI 加密后保存到数据库元数据；界面只获得是否已保存。手动导出的密码不持久化。换密码只影响新备份；改为明文会清除保存的密码。备份加密不代表当前历史数据库已加密，也不抵御同一 Windows 用户下的其他程序。密钥使用后清理 Buffer；JavaScript 字符串的内存清除无法保证。

加密 API 依据：[Node.js Crypto 文档](https://nodejs.org/api/crypto.html)。实现使用标准库原语，文件格式有错误密码和篡改测试，尚未经过独立安全审计。

## 自动计划与保留

默认关闭。启用后可选 1–168 小时间隔、1–100 份保留数量；默认 24 小时 / 7 份。应用每分钟检查到期时间，启动及系统恢复时补做一份，不逐份重放错过的计划。退出期间不运行独立任务。失败保留上一成功记录，15 分钟后重试，页面显示错误；后台失败也通过应用状态提示。

写入前在独立内存数据库演练导入，再写入同目录专用临时文件，同步并原子改名；随后重新读取、核对完整文件哈希、解密和校验。只有新备份校验通过，才按数量清理当前资料身份对应的自动文件。手动导出、其他资料的文件、目录和符号链接不会被保留规则删除。保留范围由固定名称格式和当前资料身份限定。

v0.4.1 将自动备份、加密导出及设置页的普通导出放入 Node 工作线程。只读 SQLite 事务取得一致快照，关闭读事务后执行序列化、演练、加密和落盘。WAL 允许主进程继续写入；快照之后的记录留在当前历史，由下次备份保存。列表和保留策略查询剔除完整 payload，减少主线程复制大正文。

备份、备份设置变更与目录迁移互斥，防止位置或密码在任务中途改变；普通历史采集继续运行。工作线程上限 180 秒，异常退出/超时清理本任务的临时文件并释放状态，可再次备份。退出等待串行写入与后台任务完成后再关闭数据库。约 110 MiB 数据量已做真实剪贴板并行测试；并不代表全容量、多天驻留或所有磁盘环境已验证。

## 恢复流程

从文件或当前自动备份列表选择 → 必要时输入密码 → 校验文件与结构 → 在内存数据库试导入 → 展示数量摘要 → 用户确认合并。

选取文件时保存内容哈希，预览前再次核对；文件被修改时要求重选。密码错误或预览失败使旧校验结果失效。确认仅使用已验证快照，不在确认后重新读取可能被替换的文件。取消或十分钟到期会销毁待恢复快照。合并使用 SQLite 事务，原记录和本机服务设置保留。

手动导出不能覆盖当前、默认或上次目录的数据库、日志和位置配置文件。原有“设置”页的导出保持明文 JSON；“数据与备份”提供加密与恢复向导。

## 启动失败时恢复（v0.4.1）

恢复窗口使用单独 preload 和受限 IPC，只能读取错误、选取来源、校验、确认或退出；普通历史 API、托盘和剪贴板采集在资料成功打开后才启动。

已有资料目录以只读连接检查 SQLite、记录结构、元数据及表内容指纹。确认时 `VACUUM INTO` 创建新数据库，再核对指纹，来源改变则拒绝本次恢复。备份需要解密、结构检查和试导入，错误密码或取消不写入资料。恢复预览在十分钟后释放。

新副本位于默认用户目录的唯一 `recovered-*` 文件夹；复制已有库保留内容和日常设置，从备份导入则遵守其导出范围。v0.5 起清除副本中的局域网身份、信任与同步目录，去除共享标记，需要重新配对，避免克隆旧设备身份。新副本暂停记录、关闭自动备份并同步到磁盘，通过复查后才原子提交位置配置。原始位置文件会先逐字节另存，提交失败只清理本次新建副本；原数据库、备份与其他文件保留。此流程用于重新连接健康副本，不尝试修复损坏 SQLite 的数据页。

## v0.7 数据库保护补充

数据库与便携备份分别加密。新增加密目录、密钥包装、转换/清理、独立解锁窗口与锁定生命周期，详见《历史加密设计》。恢复已有资料改为逐表复制并核对逻辑指纹，支持带密钥的源和目标，不生成明文中间库。原普通迁移仍使用 VACUUM INTO；加密迁移核对继承密钥后的副本。

备份工作线程直接读取加密快照；密钥仅通过内存传入。锁定取消未完成备份，清理本任务临时文件；已完成原子写入的备份可能仍保留，后续可重新校验。启动恢复清除 Hello 本机包装。导出图片、脚本和备份均保护当前数据库、日志、位置和密钥文件名，防止另存误覆盖。
