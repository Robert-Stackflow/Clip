# 历史加密与锁定（v0.7）

## 目标与边界

在现有 Windows 工作台上增加可选的本机数据库加密。默认资料保持兼容，用户在“数据与备份 → 历史保护”主动启用。历史正文、富文本、PNG、来源、标签、模板、分类、脚本及数据库内设置均进入加密页；数据库与 WAL 不保留这些内容的明文副本。

此功能保护关闭后的数据库文件，并限制锁定期间的应用访问。它不保护已解锁进程免于同一账户的恶意程序、管理员、内存转储、系统交换/休眠文件或屏幕捕获。路径配置、数据库大小、文件时间及 Electron 自身运行文件不隐藏；文件记录引用的源文件和用户主动导出的文件不自动加密。原明文数据库须在确认后清理，普通删除不保证物理安全擦除。

## 密钥与文件格式

数据库使用 `better-sqlite3-multiple-ciphers 13.0.3` 的 Node-API 原生模块，SQLite3 Multiple Ciphers 2.4.0，ChaCha20 页加密及完整性校验，明文页头长度为 0。数据库随机密钥为 32 字节，直接通过 native key API 传入，不放入 SQL、命令行、环境变量或磁盘文件。临时 SQLite 数据位于内存。正常未加密资料继续使用 Node 内置 SQLite，schema 保持 3。

每个加密目录必须同时保留 `history.sqlite` 和 `history-vault.json`。运行中的 WAL 仍参与事务，迁移/导出请使用应用入口，不要直接拷贝正在写入的单个数据库文件。

`history-vault.json` v1 保存资料密钥的两份独立包装：

- 密码 12–1024 字符，随机 16 字节盐，scrypt（N=32768、r=8、p=1、32 字节输出），AES-256-GCM 包装随机数据库密钥。
- 恢复密钥独立随机生成 32 字节，以 `C7-` 加 base64url 展示，同样使用 AES-256-GCM 包装数据库密钥。
- GCM 使用随机 12 字节 IV、16 字节标签，以资料 UUID 和密码/恢复角色作为附加认证数据。密码、恢复密钥与原始数据库密钥均不直接保存。
- 本机 Hello 凭据可选；自动锁定时间为 0–120 分钟，默认 15 分钟。配置文件严格限制大小和字段，校验失败不创建空资料。

更改密码只重新包装同一个数据库密钥，恢复密钥保持有效。旧加密目录和旧备份仍使用旧密码；这不是密钥撤销或对旧副本的远程更新。密码和恢复密钥同时丢失时没有后门。

## 启用、迁移与清理

输入并确认密码 → 生成恢复密钥 → 用户保存并填写完整密钥 → 创建新加密库 → 逐表复制并验证逻辑指纹 → 同步文件 → 原子切换位置配置。

首次转换使用新的 `encrypted-*` 目录。目标从创建时就带密钥，不先生成明文中间数据库再加密。串行写入与备份互斥；结束 AI/脚本、截图和共享，成功后服务绑定到新 Store。失败且尚未提交位置时保留原库，只清理本次创建的目标文件。恢复密钥准备有效期十分钟；此期间暂停剪贴板采集，结束/取消/过期后不补录密钥所在的当前剪贴板。

原明文库先保留。加密目录保存带 HMAC 的原副本路径、资料身份和逻辑指纹；用户点击“清理原明文副本”后再次校验当前加密库与原副本，再仅删除原目录的 `history.sqlite`、`-wal`、`-shm`。其他文件、历史导出和先前迁移副本不扫描、不删除。原副本改变或清理信息被改动时拒绝删除。清理失败保留状态，允许重试。

后续加密迁移保留加密状态，复制密钥包装与待清理原副本信息，先验证目标再切换位置。旧加密目录保留，不受当前目录之后的密码修改影响。

## 锁定与解锁

受限解锁窗口具有独立 preload 与 IPC，仅能查询锁定状态、解锁、进入资料恢复或退出。普通历史 API 不暴露在该窗口；主进程同时检查窗口、顶层 frame、URL、锁定状态与会话代次，入队时已授权的请求也必须在执行时仍属于当前会话。

手动锁定、Windows 锁屏/休眠事件和系统空闲超时均会：立即拒绝新历史访问，销毁主/快捷窗口，停用粘贴快捷键，停止网络监听，取消截图、AI、脚本与备份工作线程。已开始的文件操作和串行任务退出后，清理预览和临时文件，关闭 SQLite、清空撤销与列表引用、清除主进程持有的密钥缓冲区，再将解锁页标为“历史已锁定”。等待期间明确显示“正在关闭资料”。

锁定不改写系统剪贴板。解锁不补录锁定期间的内容，也不自动重启限时网页共享；已配置的局域网同步在解锁后恢复。外部 URL 请求仍须普通界面确认。Windows 会话处于锁定/睡眠状态时拒绝解锁；晚到的身份验证结果不能绕过会话检查。

密码失败有短暂重试间隔。恢复密钥解锁要求设置新密码。应用使用完密钥后清空可控 Buffer，但不能保证 JavaScript 字符串、运行时内部副本或操作系统页面立即物理擦除。

图片拖出需要短暂的本机明文 PNG。正常完成/锁定清理；启动扫描本应用固定命名的残留临时文件，不递归删除任意目录。断电、崩溃或操作系统阻止删除时仍可能留下临时文件，不将其描述为全磁盘加密。

## Windows Hello

通过 WinRT `IUserConsentVerifierInterop::RequestVerificationForWindowAsync`，传入本进程真实 HWND，以 PIN/人脸/指纹进行系统同意验证。只有 `Verified` 返回值允许继续；取消、超时、失败和锁定均拒绝。异步操作可取消，COM 引用和 HSTRING 及时释放。

启用时先验证 Hello，再用 Electron safeStorage（当前 Windows 用户的 DPAPI）保存本机密钥包装。再次解锁先验证 Hello，再解开包装。这是应用层重新认证加 DPAPI，本实现不声称把密钥绑定到 TPM 或要求硬件认证才能从同一用户上下文解密；需要防御同账户恶意代码时请保持 Hello 关闭，并使用设备级防护。

当前机器实际可用性查询已验证，成功/拒绝/晚到结果用注入验证器覆盖。真人 PIN/生物识别确认及无 Hello 设备上的实际提示仍待人工验收，不将 mock 当作真人验证。

## 备份、恢复与兼容

导出线程获得临时内存密钥，直接从加密数据库读取一致快照，之后按用户选择生成独立密码的 `.clipper` 或明文 JSON。历史解锁密码、恢复密钥、Hello 包装不会进入便携备份。历史加密与备份加密是两套独立设置；“设置”页普通导出仍明确是明文。

完整加密目录恢复要求密码或恢复密钥，创建的恢复副本仍然加密，清除 Hello、本机同步身份与信任，并暂停记录和自动备份。恢复过程中检查来源配置与内容指纹，保留原文件。若当前位置明确标记加密，即便密钥包装损坏/丢失，从普通资料或备份恢复也要求新密码和新恢复密钥确认；位置文件中 v1 的 `encrypted` 标记用于保存这一事实。位置文件完全损坏、无密钥包装时无法自动判断旧资料保护方式。

未启用加密的旧资料仍可正常升级。启用加密后 v0.6 及更旧版本不能直接打开该数据库；不要把旧版本指向正在使用的加密目录。回退应使用单独保留的旧资料或受支持的便携备份。
