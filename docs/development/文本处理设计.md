# v0.3 文本处理实施方案

本阶段承接开发计划的 AI、脚本、URL Scheme；功能参考 OneClip 的本地/在线模型、总结翻译及脚本能力。保留已有本地剪贴板核心。

## AI 操作

从选中文字打开翻译、总结、改写或自定义指令面板。先预览可编辑输入、模型、实际请求地址，再主动发送。Ollama 使用 /api/chat；LM Studio 与在线兼容服务使用 /chat/completions。支持多个服务、默认服务、模型列表、输出长度、等待时间和可选温度。在线兼容接口可选择 max_tokens 或 max_completion_tokens。

本地服务限制为回环地址；远程接口要求 HTTPS，禁止在地址中嵌入用户名、密码、查询或片段。不跟随重定向。更新地址时需清除或重新填写旧密钥，避免原密钥被发送到新服务。服务配置修订后，旧预览不能继续发送。

密钥经 Electron 异步 safeStorage 使用 Windows DPAPI 加密，renderer 只知道是否已保存。历史备份不含服务配置或密钥。此保护不抵御同一 Windows 用户下运行的其他程序。模型可能计费，由服务商决定；不自动重试失败请求，不自动发送其他历史。

模型返回内容按纯文本展示，可编辑后复制、另存历史或替换当前文字记录。替换时核对原记录内容哈希，防止覆盖期间发生的新编辑。输出不执行 HTML、脚本、链接或模型工具调用。

## JavaScript 文本脚本

脚本函数体只接收 input 字符串并返回字符串。运行时放在独立 Electron utilityProcess 中的 QuickJS WebAssembly 引擎，不向脚本注册文件、网络、环境变量、Node、Electron 或系统剪贴板接口。每个任务使用新的运行时，限制堆内存、调用栈、执行时间和结果长度，主进程另设终止计时器。

保存脚本时声明“仅选中文字”权限；运行前预览代码与输入并确认同一权限。编辑后修订号改变，旧预览不能执行新代码。失败、取消、死循环和超大输出不修改历史或剪贴板，成功结果也由用户决定如何应用。脚本备份独立导出/导入，导入不自动执行。

## 外部 URL 动作

采用 clipper-win://，在“文本工具”中由用户主动注册/移除；不覆盖其他应用已占用的协议。允许 open、search?q=、add?text=、copy?text=。拒绝未知动作、重复或额外参数、凭据、路径、片段、超长输入。打开/搜索只切换界面；新增/复制必须在应用内预览确认。URL 不接受命令、文件读取、脚本代码、模型地址或自动粘贴。

## 验收

验证三种协议的请求/结果结构、地址及密钥约束、模型列表、错误/超时/取消/响应上限、密钥落盘和重启、预览后应用及过期替换保护。模型服务协议使用隔离的本地测试服务器；是否完成真实模型推理需另行记录，不将协议测试描述成实际模型质量验收。

脚本验证正常转换、代码错误、访问宿主失败、死循环、内存/输出限制、取消和崩溃后继续运行。URL 验证允许/拒绝矩阵以及确认前无写入副作用。发布包重测相同流程。
