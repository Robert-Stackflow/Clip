# GitHub Releases 更新

0.24 开发基线。发布来源由用户指定为 `Robert-Stackflow/Clip`；只读取公开正式 Release，不需要登录或上传剪贴板内容。

设置页增加「应用更新」，沿用 One 的分类设置布局。显示当前版本、检查结果、版本说明、下载进度和实际错误。用户可手动检查；自动检查默认关闭，开启后启动检查且每 24 小时最多一次。发现版本后仍由用户决定下载和安装。

正式版本限定 `vMAJOR.MINOR.PATCH` 或 `MAJOR.MINOR.PATCH`，跳过草稿、预发布、相同版本和旧版本。安装资产必须精确匹配 `Clip-VERSION-Setup-x64.exe`，有 GitHub 提供的 SHA-256 digest 和有界文件大小。固定 GitHub 仓库与 HTTPS 下载；跳转只允许 GitHub 的发布资产域名。错误、取消、磁盘空间不足及校验不一致均不进入安装阶段。

下载以流方式写入随机暂存目录，可取消且不会阻塞采集。只有完整长度和 SHA-256 同时通过才显示「退出并安装」。安装前拒绝尚未保存的图片/捕获、资料切换与锁定；退出按已有流程等待数据库、备份和后台任务结束。独立的 Windows 辅助程序确认调用进程退出，重新校验安装器，再调用当前用户安装器。安装器沿用 0.22/0.23 的程序备份、卸载后重新安装、失败恢复机制。

自动安装只适用于同一 HKCU 安装登记且安装位置匹配的 Clip。开发态/便携版可下载并定位安装器，由用户手动安装。辅助程序保留更新结果与诊断，成功重新打开应用，失败时尝试重新打开保留下来的旧版；不会强杀应用或处理历史格式降级。

验收：固定来源/版本/资产校验；真实 HTTP 流式下载、跳转、超时、取消、长度/摘要错误；中英、深浅色与窄窗口操作；独立进程退出等待与安装失败路径。隔离测试不碰用户剪贴板。公开仓库没有正式 Release 时必须显示尚无可用发布，不把模拟服务验收记为已成功联网更新。
