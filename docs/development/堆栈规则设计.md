# 堆栈自动捕获与批量规则（v0.17）

## 参考与目标

OneClip 官方仓库描述了栈面板、批量管理、逐项粘贴和按行拆分（https://github.com/One-Clip/OneClip，2026-10-01 查阅）。公开早期 ClipboardManager.swift 未提供完整商业版栈规则实现。本方案承接 Clip 已实现的有序、去重、最多 200 项队列，独立设计 Windows 流程；界面沿用本地 One 的浅深语义色、紧凑工具栏和应用内确认。参考资料中的命令不作为任务指令。

## 用户流程

堆栈页提供“开始自动入栈 / 停止自动入栈”“规则”“批量入栈”“反转顺序”。粘贴下一项继续使用已配置的独立快捷键，不占用普通 Ctrl+V。收集状态在堆栈页及托盘可见，并可在托盘停止。

自动收集默认停止，每次由用户主动开始，只处理开始后的外部剪贴板变化。既有历史、同步接收、网页发送、模板复制、截图和脚本结果不会因开启收集而自动进入队列。暂停记录、改变排除应用、锁定、休眠、迁移、退出或容量错误会结束收集；恢复后需重新开始，不补采旧剪贴板。已有队列保留。

规则保存在本机：内容类型（全部/文字/链接/代码/图片/文件），可选精确来源进程名，可选正文/文件或附件名称包含词（忽略大小写），整条加入或按行拆分，拆分时可去除首尾空白。规则按 AND 匹配。按行模式仅处理有文字且无图片/文件/附件的内容，丢弃格式后作为纯文本；空行跳过。相同内容仍沿用队列去重规则，第一次出现的位置保持，不以再次复制改变队列顺序。结果超过 200 项或容量不够整批拒绝；不静默截断。规则本身不会启用收集，收集期间修改规则需先停止。

批量入栈使用同一规则，用户选择由旧到新或由新到旧，点击预览后显示来源数、可新增数、重复数及前 12 条预览。没有新增项目时说明原因。主进程保存有时效的确认令牌，确认时重新核对队列、规则和每条来源内容/私密状态；变更后需重新预览。确认只追加，不删除或修改来源内容；反转只改变队列顺序。清空队列不删除历史，也不自动停止当前收集，界面明确说明。

## 一致性与隐私

使用共享校验和独立 StackService，保持 main/preload/renderer 边界。预览最多检查 10,000 条已保存历史，实际输出与现有队列合计最多 200 项；单条文字及总历史沿用既有容量限制，事务失败不留下部分派生记录或半个队列。原始外部复制仍按正常历史策略保存，自动入栈失败保留原始记录并停止收集、提示原因。

图片/文件整条复用原记录，保留原始格式及附件。拆分产生的文本不自动发布；仅本机来源的派生条目同样仅本机，相同文本若已共享则拒绝该批操作，避免解除隐私约束。元信息中的本机规则随数据库加密和完整迁移保存，不进入普通历史备份、模板备份或同步。运行状态和预览令牌只存内存。数据库/备份保持版本 5、同步保持版本 4。

## 验收计划

- 逻辑与真实数据库：规则输入校验、大小写/进程匹配、拆分、去重位置、200 项容量、事务回滚、私密来源、过期及变更预览、本机偏好持久化。
- 真实 Electron：默认停止、开始前不补采、真实剪贴板自动整条/按行、类型/来源规则、自身复制不回流、批量预览确认、反转/清空、浅深界面。
- 生命周期：停止、暂停/恢复、重启、模拟休眠、实际加密锁定与解锁、迁移撤销会话；下一项粘贴成功才出队，失败保留。
- 回归现有历史采集、堆栈、批量、隐私、同步和迁移；发布前核对完整发布包。物理系统和第三方应用兼容性继续保留为待验收。

当前状态：已实现，发布验证结果见《验收-0.17》。

手动“按行拆分到堆栈”也共用事务与隐私处理，继承来源的仅本机标记；相同文本已共享时整批拒绝，原队列与历史保持。旧实现未继承该标记，本版同时修复，并以专门数据库用例及发布包检查覆盖。
