# 截图与录制-需求文档

> 2026-10-09：本文需求由独立应用 Frame 承接。Clip 已移除内置截图、录制、图片编辑和贴图实现，未来图片编辑互通保留在 Clip 待办中。

整理日期：2026-10-08，迁出说明更新于 2026-10-09。适用项目：Frame，当前以 Windows 桌面端为主要目标。需求最初在 Clip 中讨论，现已确定迁移为独立应用。

本文汇总用户明确提出的截图、标注、贴图、录屏、录音和 GIF 需求，以及随后提出的补充建议。它是后续设计、开发和验收的需求基线，不表示这些功能已经实现，也不承诺交付日期。

**产品方向更新：** 用户已选择“独立应用，迁移整套截图与录制功能”。截图、标注、贴图、录屏、录音、GIF 和识别整体归入 Frame；Clip 保留剪贴板管理及相关预览、复制和粘贴。两款应用独立安装、运行和更新，通过系统剪贴板或用户主动交付的文件协作。迁出的实现已从 Clip 移除；Frame 的功能完整性仍需在 Frame 仓库单独验收，应用间 URI 互通本轮不处理。

## 1. 需求来源与范围

### 1.1 来源标记

| 标记 | 含义 | 使用方式 |
| --- | --- | --- |
| U | 用户本次明确提出的功能需求 | 属于目标功能范围 |
| C | 用户此前提出、与截图及录制相关的约束 | 后续功能需兼容这些行为与界面要求 |
| S | 助手提出的补充建议 | 保留为候选能力；优先级是建议，不代表用户已经逐项确认 |
| 待明确 | 原始表述存在歧义，或具体交互尚未定义 | 保留原始意图，不能以暂定解释代替最终定义 |

本文中的“应”描述目标行为；“建议”描述候选方案。各项完成情况以后续实现和实际验收为准。

### 1.2 本次范围

1. 截图：来源选择、精确选区、就地标注、长截图、识别与捕获后处理。
2. 贴图：将剪贴板内容置顶显示，并提供变换、透明度、穿透及分组。
3. 录屏：显示器、窗口、区域，声音来源、编码与质量控制、摄像头及录制标注。
4. 录音：系统声音、麦克风、双源与纯录音。
5. GIF：录屏、导入视频及摄像头素材的转换、编辑和导出。
6. 应用自身能力：快捷键、剪贴板读写、设置、任务中心及结果交付。
7. Clip 联动：两款应用同时运行时，截图结果可经系统剪贴板进入 Clip，录制期间仍可使用 Clip 的快捷面板；联动不成为独立应用运行的前提。

**范围更新：** 用户此前要求移除 OCR，但最新截图需求明确包含 OCR、翻译、表格识别和 LaTeX 识别。本需求文档按最新要求将它们纳入。早期调研文档中“排除 OCR”的范围说明属于当时记录，不能用于排除本次新需求。

### 1.4 产品独立性

1. 本文全部 U 类功能归新应用；S 类建议仍作为新应用的候选能力。
2. 新应用不要求安装、启动或登录 Clip，能够独立完成截图、标注、录制、预览和导出。
3. 新应用拥有独立设置、快捷键、托盘、开机启动、任务队列、数据目录、安装包及更新机制。
4. 不共用 Clip 的历史数据库、加密密钥、用户配置或未保存录制状态。
5. Clip 不再承载本套截图与录制工作台；图片记录的查看、复制、粘贴和保存继续属于剪贴板管理。
6. 现有图片编辑功能整体迁移到新应用；Clip 保留“编辑图片”入口，通过 URI 等方式调用独立编辑器。图片预览、复制、粘贴和保存仍在 Clip 内完成。
7. 界面风格可延续既有一致性要求，应用的运行、存储和更新仍保持独立。

### 1.5 图片编辑迁移与互通

| 编号 | 用户补充需求 | 目标行为 |
| --- | --- | --- |
| U-LINK-01 | 迁移现有图片编辑功能 | 现有图片裁剪、旋转、镜像、标注、撤销重做及导出等功能归入独立应用，复用适用的编辑模型 |
| U-LINK-02 | URI 等方式互通 | Clip 能从图片记录唤起独立编辑器；新应用也能独立打开文件或剪贴板图片，不依赖 Clip 历史 ID |

建议采用“URI 唤起 + 受控素材交接”：URI 携带动作、协议版本和请求凭据，不携带整张图片或数据库密钥。编辑结果可复制到系统剪贴板，或通过对应请求回传 Clip，默认保存为新记录。原图保留、取消不产生新记录；结果回传方式不能导致同一结果被重复写入。

联动需要处理工具未安装、协议未注册、并发请求、请求过期、Clip 退出或历史锁定等情况。具体协议草案见拆分方案，当前尚未实现该图片联动协议。

## 2. 目标体验与主要流程

以下流程为组织需求的建议，具体入口与默认行为在界面设计时落实。

| 场景 | 目标流程 |
| --- | --- |
| 快速截图 | 快捷键唤起 → 检测或拖动选区 → 直接复制 |
| 截图并标注 | 选区 → 在同一会话中标注 → 复制、保存、贴图或执行动作组合 |
| 长截图 | 选择滚动区域 → 滚动并实时查看拼接 → 调整结果 → 输出 |
| 贴图参考 | 剪贴板内容 → 置顶贴图 → 缩放或调整显示 → 分组管理 |
| 录屏 | 选择来源、声音和质量 → 开始 → 暂停或标注 → 停止 → 预览、编辑、导出 |
| 纯录音 | 选择声源 → 调整音量 → 开始 → 暂停或继续 → 停止 → 预览、导出 |
| 制作 GIF | 录屏、视频或摄像头素材 → 选择片段 → 编辑帧与播放节奏 → 预览体积和效果 → 导出 |

建议让选区、标注与输出连续完成，避免强制用户先保存到历史，再进入另一个页面编辑。

## 3. 用户明确需求：截图

### 3.1 来源与选区

| 编号 | 功能 | 目标行为 |
| --- | --- | --- |

| U-CAP-02 | 窗口截图 | 选择目标窗口进行截图；界面清楚表达捕获范围 |
| U-CAP-03 | 显示器截图 | 在多显示器环境中选择指定显示器 |
| U-CAP-04 | 矩形选区 | 拖动创建矩形，并允许在确认前调整位置和大小 |
| U-CAP-05 | 窗口与界面元素检测 | 自动识别鼠标所在位置的窗口或界面元素，显示可选范围 |
| U-CAP-06 | 滚轮切换元素 | 在检测到多个候选范围时，通过滚轮切换选中的元素或层级 |

### 3.5 快捷键

| 编号 | 功能 | 目标行为 |
| --- | --- | --- |
| U-KEY-01 | 截屏 | 用可配置快捷键打开截屏流程 |
| U-KEY-02 | 截屏并自动复制 | 用独立快捷键触发截图，并在确认后直接复制结果 |
| U-KEY-03 | 自定义截屏 | 提供自定义截屏入口；所绑定的模式、参数或预设范围待定义 |
| U-KEY-04 | 贴图 | 用可配置快捷键将适用的剪贴板内容转为贴图 |

这些快捷键应统一放入新应用的“设置 → 快捷键”，支持清空、重新录入及冲突提示。冲突提示放在对应设置项附近，避免与设置项脱离。Clip 与新应用各自注册所属快捷键，两款应用同时运行时需验证冲突行为。

## 4. 用户明确需求：录屏、录音与 GIF

### 4.1 录制区域

| 编号 | 功能 | 目标行为 |
| --- | --- | --- |
| U-REC-01 | 显示器录制 | 选择指定显示器并录制 |
| U-REC-02 | 窗口录制 | 选择指定窗口并录制 |
| U-REC-03 | 区域录制 | 选择矩形区域并录制，显示当前录制范围 |

窗口尺寸改变、来源关闭、显示器断开等情况应有明确处理，不应无解释地丢失已经录下的内容。

### 4.2 声音来源

| 编号 | 功能 | 目标行为 |
| --- | --- | --- |
| U-AUD-01 | 系统声音 | 捕获系统播放的声音 |
| U-AUD-02 | 麦克风 | 选择麦克风并捕获声音 |
| U-AUD-03 | 原生双源 | 同时捕获系统声音与麦克风，并保证同步；具体原生实现另行设计和验证 |
| U-AUD-04 | 纯录音 | 提供不录制画面的音频模式，支持系统声音、麦克风或双源 |

“原生双源”不以仅出现两个声音开关作为验收结果；需验证真实采集、同步和设备变化行为。独立音轨属于下文补充建议，不能默认视为原始需求已明确要求。

### 4.3 录制控制与质量

| 编号 | 功能 | 目标行为 |
| --- | --- | --- |
| U-REC-04 | 暂停与继续 | 暂停时不增加有效录制时长，继续后保持画面与声音连续性 |
| U-REC-05 | 编码器控制 | 提供适用的编码器选择，并展示本机实际可用能力 |
| U-REC-06 | 质量控制 | 提供清楚的质量选项，必要时开放分辨率、帧率、码率等高级参数 |
| U-REC-07 | 摄像头 | 将摄像头作为素材来源或录制叠加画面；两种模式的具体范围待明确 |
| U-REC-08 | 录制标注 | 录制中进行标注；显示方式、持续时间及是否写入结果需明确 |
| U-REC-09 | “简述”相关能力 | 保留用户原文“简述/摄像头/录制标注”；暂按“键鼠展示”理解，仍待明确 |

如 U-REC-09 指键鼠展示，候选范围包括鼠标指针、点击效果和按键提示；如指解说，则需要另行定义解说录入、字幕或旁白流程。

### 4.4 GIF 素材入口

| 编号 | 功能 | 目标行为 |
| --- | --- | --- |
| U-GIF-01 | 录屏转 GIF | 录制屏幕素材并转换为 GIF |
| U-GIF-02 | 导入视频转 GIF | 导入视频，选择转换范围并输出 GIF |
| U-GIF-03 | 摄像头转 GIF | 捕获摄像头素材并输出 GIF |

三种入口建议共用素材预览、编辑和导出流程。GIF 不包含声音；含声音的视频或摄像头素材在转换时应清楚表达这一结果。

## 5. 助手补充建议：优先考虑

以下均为 S 类候选建议，按“先保证材料可靠，再完善编辑与输出”的顺序组织。

| 编号 | 建议 | 用户价值与候选范围 | 建议优先级 |
| --- | --- | --- | --- |
| S-01 | 异常恢复与保留录制 | 应用崩溃、编码异常、慢盘或导出失败后，尽量保留已完成素材；恢复草稿有明确保留与清除策略 | P0 |
| S-02 | 延时截图与记忆选区 | 支持倒计时，便于截菜单和悬浮状态；复用上次区域或固定尺寸 | P1 |
| S-03 | 多区域与多显示器 | 同次捕获多个区域，支持多屏选择和跨屏截图；多区域组合录制作为进一步扩展 | P2 |
| S-04 | 可再次编辑的截图工程 | 保存原图、标注和变换，重新打开后继续修改，独立于最终 PNG 等图片导出 | P1 |
| S-05 | 录制中截图及使用快捷面板 | 演示录制时可截关键画面、打开最近记录和快捷回复；控制界面是否进入画面有明确规则 | P1 |
| S-06 | 独立声音控制 | 系统声和麦克风分别调音量、静音和查看电平，提示过载；进阶提供独立音轨 | P1；分轨 P2 |
| S-07 | 按应用采集声音 | 只录目标应用，减少无关通知和其他播放声音；按系统能力显示可用性 | P2 |
| S-08 | 轻量视频后期编辑 | 裁剪画面、裁掉头尾、删除中间片段、调整速度和音量；避免为简单处理再打开另一款工具 | P1 |
| S-09 | GIF 帧编辑与导出预览 | 删除及重排帧、逐帧延时、倒放、往返、循环；在导出前比较质量和预计体积 | P1 |
| S-10 | 后台导出与任务队列 | GIF、视频等耗时导出进入任务中心，支持进度、取消及失败重试，保持主界面可操作 | P1 |

优先级含义：P0 为素材保护与可靠性底座；P1 为高频工作流程；P2 为增强能力。它不是工期估算，也不削减 U 类目标范围。

### 5.1 异常与恢复建议细化

1. 区分用户主动放弃、正常结束、可保存的提前结束和无法完成的录制。
2. 导出失败后保留预览及素材，重试导出，不要求重新录制。
3. 遇到磁盘不足、容量上限、设备断开或编码停止时，优先受控停止并保存可用内容。
4. 可恢复草稿需明确是否开启、保存位置、保留期限和清除方式，沿用适当的数据保护。
5. 提前显示录制时长、文件大小及空间限制，不用一个笼统错误解释所有停止原因。
6. 长时录音的分块、采样与文件上限保持一致，不能出现界面允许的时长远高于实际可录时长。

### 5.2 声音控制建议细化

1. 系统声与麦克风分别选择设备、调音量、静音和显示电平。
2. 根据用途提供人声或原声预设，降噪和回声处理可理解、可调整。
3. 进阶模式保留独立音轨，便于后期分别处理。
4. 设备拔出、默认设备切换及蓝牙模式变化有明确反馈。
5. 纯录音流程不依赖屏幕来源选择，界面只保留音频所需操作。

### 5.3 GIF 编辑建议细化

1. 使用轻量时间轴或帧列表，支持删除、重排及选择片段。
2. 调整帧延时、播放速度、倒放、往返和循环方式。
3. 支持裁剪、缩放以及必要的文字、水印或按键提示。
4. 预览尺寸、帧率、颜色与优化策略对清晰度及文件体积的影响。
5. 导出前展示预计体积，导出后展示实际体积；预计值不冒充最终结果。
6. 屏幕、视频与摄像头入口复用同一编辑体验。

## 7. 既有约束与整体交互

本节的界面一致性原则适用于新应用；快捷面板约束属于 Clip 及两款应用的联动验收，不要求新应用再实现一套 Clip 快捷面板。

### 7.1 设置与界面一致性

| 编号 | 用户既有约束 | 本模块的落实要求 |
| --- | --- | --- |
| C-UI-01 | 统一设置页面排版与布局 | 截图、录制、声音、GIF 等设置使用一致的页面宽度、间距和分组方式 |
| C-UI-02 | 统一设置卡片样式 | 卡片标题、设置项标题和说明文字保持统一排版 |
| C-UI-03 | 设置项 title 不加粗 | 设置项标题使用常规字重；卡片标题与说明采用统一层级 |
| C-UI-04 | 逻辑清晰、简洁且不冗余 | 按任务分组，不在多个页面重复同一设置；快捷键集中管理 |
| C-UI-05 | 弹出层效果一致 | 菜单、选择器及相关弹窗沿用统一边框、阴影与动画；减少多余分割线 |
| C-UI-06 | 提示不引起布局抖动 | 校验提示在稳定位置显示，采用应用组件，不依赖系统原生表单提示 |

截图结果的圆角、边框和阴影是用户可设置的输出效果，与操作界面本身的卡片或弹窗样式分开管理。

### 7.2 快捷面板及原窗口焦点

以下来自此前快捷面板相关请求，也是录制联动时的验收约束：

1. 点击快捷面板之外的区域关闭面板。
2. 快捷面板应处于适当的最前显示层级，覆盖开始菜单等场景需验证。
3. 面板弹出时保留原程序输入焦点，点击内容后能向原目标粘贴。
4. 面板位置优先依据文本光标；无法取得光标时采用清楚且稳定的回退位置，沿用用户提出的窗口右下角意图。
5. 最近记录、快捷回复等入口及卡片底部区域均能触发对应的粘贴或复制。
6. 录制过程中可唤出快捷面板，不能因录制状态笼统屏蔽这些入口。
7. “悬浮时展示预览弹窗”在“设置 → 桌面交互”中可配置，默认开启。

这些行为不以某一个输入框可用作为全面完成依据；需覆盖 Clip 内部、普通应用、浏览器和 Windows 开始菜单等场景。

### 7.3 建议的入口与分组

1. 截图、录屏、纯录音有清楚的直接入口，避免所有操作都先经过复杂设置页面。
2. 高频工具可直接操作；高级参数按需展开。
3. 录制前展示来源、声音和质量摘要，录制中突出时长、暂停、停止与声音状态。
4. 停止后的结果页共用预览与输出操作；视频和 GIF 仅展示适用工具。
5. 背景导出、识别等耗时工作建议统一进入任务中心。
6. 动画反馈及时、短暂，不推迟实际可操作时点，并遵循减少动态效果设置。

## 8. 助手建议的质量与验收基线

本节是建议验收要求，不是当前实测成绩；具体性能门槛应在明确测试设备和样本后制定。

### 8.1 必须优先关注的质量问题

1. **原始清晰度：** 最终截图不使用列表缩略图代替原始图，也不静默缩小。需要缩小或受尺寸限制时明确告知。
2. **长时可靠性：** 内存不随录制时长持续线性增长；素材有受控落盘、容量与队列策略。
3. **素材保护：** 非用户主动放弃时，错误处理尽量保留可用内容，并解释恢复或导出方式。
4. **声音同步：** 双源和视频同步有真实验证；不把“选项已勾选”作为声音存在的证据。
5. **真实能力：** 编码器与硬件加速状态依据实际探测和运行结果，不能仅凭文件扩展名宣称支持。
6. **坐标与颜色：** 多屏、不同缩放、负坐标、高分辨率及 HDR 环境下，选区和结果位置、尺寸、颜色需核对。
7. **可解释回退：** 元素检测、应用音频或其他平台能力不可用时说明限制，提供适用替代流程。

### 8.2 功能验收矩阵

| 模块 | 主要验收场景 |
| --- | --- |
| 选区 | 全屏、窗口、指定屏、矩形；候选元素切换、Ctrl+A、移动及尺寸微调、取消与重选 |
| 标注 | 所有工具可用；对象修改、撤销重做、导出结果和预览一致 |
| 贴图 | 图片、文字、文件；各项变换、透明度、穿透退出、分组及多屏位置 |
| 长截图 | 普通页面、固定头尾、动态内容、滚动中断和错误匹配；结果可预览和修正 |
| 识别与翻译 | 中文、英文、混合文本、复杂表格、公式；空结果、失败、校正及复制／导出 |
| 录屏 | 显示器、窗口、区域；暂停继续、尺寸变化、来源关闭、显示器断开 |
| 录音 | 系统声、麦克风、双源、纯录音；设备切换、长时录音、样本完整性与声音同步 |
| 摄像头及叠加 | 权限拒绝、设备断开、叠加定位和缩放；录制标注及键鼠效果与预览一致 |

| 导出与恢复 | 保存取消、目标冲突、磁盘不足、写入慢、编码失败、应用崩溃、重启后恢复 |
| 联动 | 录制中截图、唤出快捷面板、粘贴、预览开关，以及控制界面是否被录入 |
| 界面 | 浅色／深色、不同窗口宽度和缩放；统一样式、标题字重、无多余边框及布局抖动 |

还应区分开发环境与正式安装包验证，避免仅在 dev 中正常。

### 8.3 性能与资源记录建议

验收记录至少说明测试机器、系统版本、显示分辨率、缩放、素材和编码设置，并记录：

- 截图唤起与确认后输出耗时。
- 录制中的 CPU、GPU、内存与落盘速度。
- 实际采集／输出帧率、丢帧或重复帧、音画偏差。
- 长时录音的时长、样本完整性和文件可播放性。
- GIF 导出耗时、文件大小及文字、渐变、动态画面的效果。
- 崩溃或提前停止后的可恢复范围。

## 9. 依赖、安装包与数据处理建议

1. 结合此前安装器体积问题，识别模型、高级编码器等较大依赖建议按需获取，不在基础安装包中无条件堆叠。
2. 下载前展示用途、体积和存放位置，提供删除、更新及失败重试操作。
3. 尽量复用适用的系统能力和已有图片编辑基础；是否引入原生助手或外部编码组件由验证结果决定。
4. 本地与在线识别能力清楚区分。调用在线服务时明确展示素材将发送到所选服务，并沿用用户配置。
5. 不将录制、截图或识别结果默认上传到网络；捕获后上传仅来自主动设置的动作组合。
6. 可恢复草稿与最终导出文件分别管理，保留期、清除方式和数据保护规则可理解。

## 10. 建议实施顺序

此顺序用于后续拆分工作，不代表用户功能已被取消或交付批次已经确认。

| 阶段 | 主要内容 | 阶段验收重点 |
| --- | --- | --- |

| B：截图与标注主流程 | 完整选区、检测与微调、基础／高级标注、快捷键、动作组合、可编辑工程 | 从唤起到输出连续完成，不强制先存历史 |
| C：贴图与长截图 | 多类型贴图、变换与分组、长截图及结果修正 | 参考内容可管理，长图不错误盲拼 |
| D：录屏与声音控制 | 来源、暂停继续、编码与质量、原生双源、独立声音控制及纯录音 | 实际画面和声音正确，同步与性能可验证 |

U 类明确需求均保留在目标范围。S 类建议按价值和资源另行选择；不要求一次性实现所有候选能力。
