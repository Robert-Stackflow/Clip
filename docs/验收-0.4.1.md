# Clipper 0.4.1 启动恢复与后台备份验收

日期：2026-10-01。Windows 11 x64（10.0.26200）、单屏 150% 缩放、Electron 44.5.1。源码目录 D:\Repositories\Clipper；发布目录 release\0.4.1\win-unpacked。

## 交付内容

启动故障恢复窗口、原目录重试、已有资料副本恢复、普通/加密备份恢复、后台导出、一致快照、备份期间继续采集及退出等待。沿用 One 的浅深配色和界面层次。

数据库仍为 schema 2，备份仍为 v3，`.clipper` 加密格式不变。修复恢复对话框在“解锁 → 预览”切换时可能被旧关闭事件取消的问题，并增加关闭顺序断言。

## 大数据并行采集实测

发布包测试使用 128 条大文本记录，数据库内记录 JSON 总计 **115,274,532 字节（约 110 MiB）**，不是模拟延时：

- 加密备份 115,275,683 字节，导出、验证完成用时 **3,437 毫秒**。
- 备份未完成前，**3 次真实系统剪贴板复制**已经进入历史。
- 六次界面资料请求耗时 **153、154、149、134、129、125 毫秒**。
- 备份包含快照时的 128 条记录；当前历史包含全部新增内容，共 134 条。
- 随后发起第二次导出并立即退出，退出后的备份仍完整包含 134 条记录。

详细数据保存在 work/backup-performance/result.json。上述结果是当前机器与该数据集的测量，不是所有设备的性能承诺。

## 范围与限制

- 已完成本轮启动恢复和备份并行优化；局域网同步、数据库加密、Windows Hello、进阶系统交互、录制、签名安装包与更新仍在开发计划中。
- 恢复流程连接健康副本，不修复损坏 SQLite 数据页。原库或备份本身无法校验时需另选可用来源。
- 备份可加密，当前历史数据库仍明文。已有目录恢复保留原配置；从备份恢复不包含未导出的设置、服务密钥或源文件本体。
- 迁移、导入、启动全面校验和恢复演练仍可能占用主进程。满 256 MiB 的长期驻留、多屏混合缩放、其他 Windows 版本、磁盘满、真实断电和硬件故障尚未完成验收。
- 当前仍为未签名 x64 解压运行包。AI 测试使用隔离协议服务，不代表真实模型推理质量或所有服务商兼容性。
