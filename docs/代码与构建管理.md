# 代码与构建管理

代码由 Git 提交和标签管理，使用一个持续更新的主工作目录。0.43 已交付代码作为初始基线，当前 0.44 继续开发；完成打包验收后再记录交付标签。

`node_modules`、`work`、`dist`、`release`、`outputs`、本机开发资料及 `.env` 不提交。依赖与 Rust 编译缓存可在受控开发机器共用，不为每个小版本复制完整环境。安装依赖和构建生成的文件不能替代代码版本记录。

发布验收可使用临时 Git worktree，从明确提交构建，并检查实际安装目录。验收结束后移除其构建目录和临时 worktree。仅保留必要验收记录，不长期保存测试浏览器资料、随机测试文件和重复源码副本。

清理对象仅限确认已停用的生成文件。源码、Git 历史、已交付程序和日常 Clipper 资料独立保留；删除目录前检查绝对路径，并先移除目录链接，避免沿链接删除目标数据。

开发使用 Electron；后续在固定工作目录运行，界面修改应直接刷新正在开发的窗口。真实剪贴板、同步和用户资料的验证范围需要与开发窗口本身区分。
