# Windows 虚拟附件

## 需求与流程

普通文件历史继续引用原路径。针对邮件等应用通过 FileGroupDescriptor / FileContents 提供、尚无本机路径的文件，保存一份有界内容副本，来源应用退出后仍能使用。界面归入“文件”，显示附件名、已保存大小与源描述时间；附件名称参与搜索、自定义分类、模板和备份。

Windows 等价实现使用 OLE IDataObject，支持 Unicode/ANSI 文件描述和 HGLOBAL、IStream、IStorage 内容。IStorage 通过有界 ILockBytes 复制为复合文档。保留文件内容、名称、创建/访问/修改时间和文件属性描述；不执行文档、脚本、Shell 移动标记或对象 CLSID。读取只发生于用户复制后的新剪贴板状态，沿用暂停、来源排除和禁止历史标记。

复制、粘贴和拖出时生成本次运行的临时文件，以 CF_HDROP 与目标应用互通；临时文件保留原名称和可用的修改时间。原描述中的创建时间/属性仍在历史中保存，不据此设置隐藏、只读或系统属性。主动“另存附件”只写新文件名，不自动打开；文件本体可随本地/密码加密备份恢复。

## 边界与生命周期

- 整组最多 256 个普通附件；拒绝目录、路径、设备名、重复文件名、路径穿越和异常描述。相同名称按 Windows 大小写规则冲突。
- 原始字节合计最多 12 MiB，包含 Base64 与元数据的单条仍受 16 MiB 限制，总历史/模板预算仍为 256 MiB。超限或部分读取失败不保存残缺组。
- 在独立 STA 辅助进程读取，父进程通过 Job 将进程内存限制为 256 MiB，读取期限 8 秒、输出 17 MiB，并管理生命周期。源应用无响应、剪贴板序列改变、锁定、休眠、退出均取消；返回后再次校验序列与会话。
- IStream 分块读取，IStorage 目标 ILockBytes 限制写入与长度，HGLOBAL 在复制前检查分配大小与声明长度，按声明长度读取，忽略分配填充字节。辅助进程不创建文件、不连接网络、不恢复文件剪切状态。
- 历史内保存附件字节，遵循已有数据库加密。临时文件只在显式复制或拖出时产生，额外限制 256 MiB 和 200 组（包括空文件组），正常退出、锁定和下次启动清理；被其他程序占用的文件仍计入预算，运行期间每秒重试，无法清理不阻止启动。强制终止会留到下次启动清理。主动另存的文件不加密。
- IStorage 保留流、嵌套存储及 CLSID；新容器的字节布局不保证与源容器相同。
- 数据库与备份版本升级为 5，旧版程序拒绝打开新库，防止静默丢弃附件。仍可导入旧备份。文件和附件不进入仅支持文字/图片的局域网同步或网页共享，同步协议保持版本 4。

## 界面与验收

沿用 One 的列表、低对比度分隔线、主题与按钮尺寸。文件详情区分“本机文件引用”和“已保存附件”；格式与信息可逐个另存，模板编辑保留二进制内容。

用真实 OLE 数据源分别提供 HGLOBAL、IStream、IStorage、多文件及 Unicode 名称；读取后关闭数据源，再复制/拖出核验字节。覆盖空文件、错误长度、非法名称、超限、超时、剪贴板变化、取消、锁定、加密备份恢复与旧版拒绝；使用独立资料目录和受控文件接收窗口。Outlook 等实际应用的兼容性需单列实测，不能用夹具结果宣称全部兼容。
