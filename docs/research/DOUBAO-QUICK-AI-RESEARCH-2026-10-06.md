# 豆包快捷 AI 窗口调研与 Clipper 设计建议

> 基线说明（2026-10-10）：保留调研日期和当时的实施状态；不继续维护本篇的进度或待办。当前实现及后续工作统一见 [当前状态与待办](../development/当前状态与待办.md)。

调研日期：2026-10-06。范围：快捷唤起、内容带入、对话与结果回到原应用。本文是调研与设计建议，尚未实施。

## 核实范围

- 用户已确认自己使用豆包时，Alt+Space 能弹出 AI 对话窗口。这是本次调研的交互基准。
- [豆包官方桌面端页面](https://www.doubao.com/download/desktop)的较早搜索索引介绍了随时唤起桌面助手、截图提问、划词处理和共享软件内容。它说明了“在当前工作场景中使用 AI”的产品方向，但不是当前版本快捷窗口的完整操作说明。
- 本次实际打开同一官方页面，页面已改为介绍工作模式、操作电脑与浏览器、AI 编辑和飞书联动。不能用较早的搜索索引推断当前窗口的具体按钮、尺寸、失焦行为或会话保存规则。
- 没有安装或登录豆包，也没有实际触发客户端快捷窗口；下面的窗口细节均明确作为 Clipper 建议，不冒充豆包实测行为。
- [Microsoft PowerToys Run 文档](https://learn.microsoft.com/zh-cn/windows/powertoys/run)确认它也默认使用 Alt+Space。因此 Clipper 如果采用此按键，需要可配置快捷键并报告注册冲突。

## 对 Clipper 的判断

值得引入独立的“快捷 AI 对话”窗口，让用户在其他软件中提问、带入文字或图片并继续追问。入口速度、对话连续性和结果回到原应用共同构成这个功能，单纯给现有 AI 处理弹窗绑定快捷键不足以达到目标。

| 现有能力 | 源码核对 | 可复用或需要补齐 |
| --- | --- | --- |
| AI 服务与指令 | `src/main/ai.ts`、`src/renderer/text-tools-ui.ts` | 复用服务配置、默认服务、Codex 登录、内置与自定义指令，不再维护一套配置 |
| 文字和图片输入 | `src/shared/text-tools.ts`、`src/main/ai-transport.ts` | 已有单次文字/图片处理；对话需要每条消息自己的文字与附件 |
| 多轮上下文 | `AIRequest` 与 `aiMessages()` 目前构造单次转换任务 | 新增会话、用户/助手消息、草稿、历史和请求状态；对话与单次处理使用不同的请求语义 |
| 逐字显示回复 | HTTP 请求设置 `stream:false`；Codex 收集增量后返回完整结果 | 新增流式事件与逐次渲染，保留取消、超时、长度限制和失败重试 |
| Codex 对话 | 每次创建临时线程，非系统消息被合并成一个文本输入 | 多轮需要真正的线程生命周期或保留角色的上下文适配，不能直接拼接所有历史文字 |
| 快捷唤起 | `src/main/hotkeys.ts`、`src/main/index.ts` | 复用全局快捷键及冲突处理，新增独立绑定 |
| 原应用粘贴 | `src/main/tray-panel.ts`、`src/main/native.ts` | 复用唤起前保存目标窗口、检查目标和恢复焦点；失败时保留复制结果并提示手动粘贴 |

## 建议交互

1. **唤起**：全局快捷键打开独立小窗口并聚焦输入框，无需展示主窗口。默认建议 Alt+Space，设置中允许修改；按键被占用时明确反馈。窗口出现在当前屏幕的可用区域，记住用户调整后的大小和位置。
2. **空态**：优先呈现输入框和少量常用指令。服务选择保持紧凑，新建对话与历史入口用统一图标按钮。沿用现有控件、浮窗动画和原生边框阴影。
3. **带入内容**：用户可以粘贴文字/图片、选择剪贴板记录或添加截图。带入内容展示为可预览、可移除的附件；仅唤起窗口不应自动读取其他应用选区或发送剪贴板。
4. **指令**：输入 `/` 选择已有指令，显示指令图标和标题。翻译等需要变量的指令只呈现对应变量；普通自由对话不强制先选择指令。
5. **连续对话**：发送后展示对话区并逐字显示回复。支持多轮追问、停止生成、失败重试、复制单条回复；服务不支持图片时明确说明。中文输入法选词时 Enter 不发送，Shift+Enter 换行。
6. **回到工作**：提供复制、粘贴回原窗口、保存为记录。Esc 收起窗口并保留草稿和对话；收起不等于取消生成。再次唤起恢复当前对话，只有主动新建才开启新会话。
7. **任务状态**：长时间生成可沿用任务中心展示状态，并能返回相应对话。任务结果与会话结果引用同一次请求，避免重复运行或重复计数。

举例：在编辑器中复制一段报错 → 唤起快捷 AI → 粘贴并问原因 → 追问解决方法 → 复制回答或粘贴回编辑器。图片使用同一路径，粘贴图片后直接提问。

## 实施顺序建议

第一阶段完成独立窗口、可配置快捷键、多轮会话、流式回复、服务切换、已有指令、文字/图片粘贴，以及复制/原窗口粘贴。草稿和会话须能在收起后恢复，基础历史在本机保存并遵循现有数据存储与锁定机制。

第二阶段再完善历史搜索、从剪贴板多选引用、截图后直接追问，以及任务中心跳回会话。自由对话作为“AI与脚本”的能力扩展，主窗口可提供查看历史的入口。

需要单独验证：多显示器和 DPI、快捷键冲突、首次加载时输入焦点、中文输入法、收起后生成完成、切换服务时的上下文边界、原目标窗口关闭或权限不同、图片模型不兼容、服务配置变更、应用锁定和数据存储切换、流式断线后重试不重复添加消息。
