# 对照 OneClip 的功能缺口与实施进展（Clipper 0.50.15）

初次核对日期：2026-10-05；实施更新：2026-10-06。对照基准为 [OneClip README](https://github.com/One-Clip/OneClip)、截至 [2.1.0](https://github.com/One-Clip/OneClip/releases/tag/2.1.0) 的公开发布说明、用户此前提供的 OneClip 界面截图，以及 Clipper 工作区源码。下表记录的是**实施前的缺口**，保留原始判断作为追溯依据；当前进展见其后的实施状态。源码核对不等于真实 Windows 应用兼容性验收。

## 初次核对的明确缺口

| 优先级 | 功能 | OneClip 依据 | Clipper 当前状态与完成边界 |
| --- | --- | --- | --- |
| P0 | 分类记录的留存语义 | 用户提供的分类编辑截图有“永久存储”；分类规则也可自动归档 | 分类模型没有“永久存储”字段。更需要先纠正现有口径：手动分类记录的 `manualCategories` **不会**让其免于自动清理；当前保护条件只包括收藏、置顶、共享、堆栈和拖拽容器。应先明确产品语义并核对清理提示，避免用户把“已归类”误认为“不会删除”。见 [`types.ts`](../../src/shared/types.ts)、[`store.ts`](../../src/main/store.ts)、[`store-index.ts`](../../src/main/store-index.ts)。 |
| P1 | 分类规则正则匹配 | [OneClip 2.1.0](https://github.com/One-Clip/OneClip/releases/tag/2.1.0) 明确新增 | 当前“内容包含”是忽略大小写的普通子串匹配，分类模型没有匹配模式。若实现，需要在规则编辑、校验、搜索 worker、备份导入之间保持一致，并限制复杂表达式的执行成本。见 [`advanced.ts`](../../src/shared/advanced.ts)、[`advanced-ui.ts`](../../src/renderer/advanced-ui.ts)。 |
| P2 | 子分类及层级管理 | 用户提供的分类编辑截图有“允许创建子分类”；[2.0.7](https://github.com/One-Clip/OneClip/releases/tag/2.0.7) 提到子标签排序 | 当前分类只有平级 `Category`，没有父分类字段、层级导航、层级规则或移动/删除子树的语义。应在数据迁移与备份兼容方案明确后再加入。见 [`types.ts`](../../src/shared/types.ts)。 |
| P2 | 收藏和快捷回复手动排序 | [OneClip 2.0.5](https://github.com/One-Clip/OneClip/releases/tag/2.0.5) 明确支持收藏、快捷回复和自定义分类拖拽排序 | Clipper 已实现自定义分类拖拽排序；收藏仍随记录顺序显示，快捷回复按 `updatedAt` 排序，没有持久化的自定义顺序和排序入口。见 [`store.ts`](../../src/main/store.ts)、[`app.ts`](../../src/renderer/app.ts)。 |
| P2（需先确认是否恢复） | 主窗口卡片视图与三种排列方向 | [OneClip README](https://github.com/One-Clip/OneClip) 描述列表/卡片切换和卡片三方向 | Clipper 保留了 `view` 设置字段与网格、纵向、横向样式，但当前主窗口渲染路径未提供切换控件，也未使用这些状态。旧样式不应被算作已交付功能；恢复前先确认是否符合当前双栏设计。见 [`types.ts`](../../src/shared/types.ts)、[`app.ts`](../../src/renderer/app.ts)、[`desktop.css`](../../src/renderer/desktop.css)。 |
| P3（可选） | 独立贴图/便签浮窗 | [OneClip 2.0.9](https://github.com/One-Clip/OneClip/releases/tag/2.0.9) 增加状态栏贴图/便签入口；[2.1.0](https://github.com/One-Clip/OneClip/releases/tag/2.1.0) 改进贴图操作 | Clipper 有图片预览、编辑和“置顶记录”，但没有把图片或便签独立固定在桌面上的浮窗工作流。与记录置顶不是同一功能。 |
| P3（可选，需明确隐私策略） | 图片上传图床并获取链接 | [OneClip 2.0.6](https://github.com/One-Clip/OneClip/releases/tag/2.0.6) 增加内置与自定义图床上传 | Clipper 的图片处理和局域网网页共享不等于上传到第三方公开图床；当前无图床配置、上传及链接回写工作流。若跟进，应默认关闭，并在上传前明确目标服务与公开范围。 |

P0 表示先处理现有行为与说明的风险；P1 是清晰的新功能缺口；P2 是需要产品设计和数据迁移的功能；P3 是可选扩展。用户于 2026-10-06 要求开始实现本节内容。

## 2026-10-06 实施状态

| 功能 | 当前实现 | 边界 |
| --- | --- | --- |
| 分类永久存储 | 分类可设置“永久存储”；匹配的手动或自动分类记录不参与按天数、条数清理和普通清空 | 仍受资料库总容量上限约束；删除分类或关闭永久存储后恢复正常清理 |
| 分类正则规则 | 内容规则可切换正则，备份、搜索和清理使用同一校验与匹配逻辑 | 为避免同步搜索和清理卡顿，限制复杂重复结构，仅匹配内容前 8192 字符 |
| 子分类 | 支持一层子分类，侧边栏缩进显示；父分类搜索同时包含直属子分类；备份可恢复层级 | 删除父分类时子分类提升为顶层，不级联删除记录 |
| 手动排序 | 收藏、快捷回复支持拖动排序，顺序持久保存；导入回复时保留原有顺序并接在后面 | 通过拖动排序把手操作，未提供键盘上下移动控件 |
| 卡片视图 | 主窗口可切换列表/卡片；卡片支持网格、纵向和横向布局 | 横向布局采用横排内容的单列卡片，避免在窄列表栏制造横向滚动和大块空白 |
| 桌面贴图/便签 | 文字或 PNG 记录可从“更多操作”贴成可拖动、缩放的小窗，并可切换置顶 | 小窗只展示当前记录快照，暂不支持在小窗内编辑；历史锁定、资料切换或系统锁屏时关闭 |
| 图片上传 | 设置中可主动启用自定义 HTTPS 图床；点击图片记录的上传操作后发送原始 PNG，验证返回的 HTTPS 链接并复制 | 默认关闭，不后台上传；尚未接入预设的第三方图床服务，需用户自行提供兼容地址 |

类型检查、构建、相关单元测试和隔离资料目录中的 Electron 联动测试已通过。联动测试覆盖父子分类搜索、卡片模式、收藏排序、贴图小窗和图床配置；实际第三方图床服务的兼容性仍需用对应服务验证。

## 暂缓或需要进一步确认

- **截图、录屏、录音体验优化**：用户已明确暂缓。OneClip 2.1.0 的录屏/录音、截图工具栏呈现改进应放在这一组，不能写成 Clipper 完全没有媒体能力。
- **“实况文本模式”**：[OneClip 2.0.9](https://github.com/One-Clip/OneClip/releases/tag/2.0.9) 只有功能名称，公开说明不足以界定完整交互；OCR 已按用户要求移除。该模式需看实际行为后才能判定，暂不据此立项。
- **Windows 真实应用兼容性**：复杂 OLE 来源、Word/Excel 富格式、跨应用拖拽、混合 DPI 与多设备同步已有实现路径，但仍缺真实环境验收证据。这属于“未验证”，不应写成“未实现”；详见 [当前状态与待办](../development/当前状态与待办.md)。

## 不列入待开发

- OCR：用户于 2026-10-07 明确要求全面移除，不因对标应用提供而重新加入。
- 独立快速粘贴面板和 PopClip 式划词菜单：用户此前明确要求移除，不因 OneClip 提供而重新加入。
- macOS Dock、Touch ID、访达剪切文件、刘海屏灵动岛、液态玻璃与 Homebrew/Sparkle：属于平台实现或视觉语言，Windows 端只讨论对应用户需求，不做原样移植。
- 高级筛选、分类拖拽排序、拖拽容器失焦自动隐藏/锁定、堆栈、快捷回复、脚本、AI、局域网同步、备份和来源应用图标：已有对应实现；后续可做体验或兼容性改进，不重复列为“从零开发”。

## 后续验收

1. 在实际使用的高历史量资料库中核对永久分类的清理速度和正则规则的匹配结果。
2. 用具体图床服务验证其 HTTPS 上传接口、返回格式和链接可访问性；如需预设服务，另行选择服务及其隐私说明。
3. 检查多显示器、不同缩放比例下的贴图拖动与缩放，并确认卡片模式在窄窗口中的可读性。
