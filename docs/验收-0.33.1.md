# Clipper 0.33.1

本轮继续优化大图片和原始格式的复制、采集与图片编辑；UI 使用已迁移的 One 基础组件和页面骨架。本轮未重新宣称新增全部页面设计。

| 项目 | 实现与边界 |
| --- | --- |
| 图片复制 | 只解码一次生成 DIBV5，不再生成未使用的缩略图；已有原始 DIB/DIBV5 仍逐字节回放，不重编码其色彩数据 |
| 原始格式 | base64 每块最多解码 192 KiB；原生内存复制通过现有 Koffi 异步接口完成，大位图视图每块最多 4 MiB；小块维持直接调用；全部准备完成后才打开剪贴板 |
| 取消 | 原生复制回调完成后再清理其 Buffer 和 HGLOBAL；锁定、会话变化或取消在提交前丢弃未转交内存；系统接收已提交格式后不再释放其所有权；部分提交失败保持既有边界 |
| 容量计算 | 对已验证的 PNG、格式和附件 base64 字段直接计长度，其余元数据按正常 JSON 计数，避免容量估计再构造整份 base64 JSON；保持原 16 MiB/256 MiB 限制和存储格式 |
| 采集预览 | 采集原始 PNG 后保留该对象的小预览；WeakMap 随对象释放，修改 PNG 后重新生成；重复使用不再解码一次，不保存原图位图缓存 |
| 截图 | 直接使用桌面捕获返回的 NativeImage，减少中间 PNG 编码/解码；截图、区域、身份及显示配置检查保留；物理捕获未重测 |
| 图片编辑 | 编辑上限先于完整解码检查；打开与提交的本地验证各只完整解码一次；等待文件选择不保留解码 Buffer；源图有效性使用哈希查询，避免每块读取整份来源图 |
| 编辑另存为 | 共用分块、刷新、异步原子提交和目标变化检查；可覆盖文件选择器明确确认的目标；补上 .png 后遇到另一已存在目标会拒绝，避免覆盖未确认的文件；关闭、取消及来源变化在提交前保留原目标；已进入原生提交后不能撤销该次保存 |

私有合成 PNG 为 10244793 字节，1600×1600 像素。图片复制和 10 MiB 原始格式各执行七个样本；计时包括实际图像处理、Windows 私有内存准备和提交适配器，不包含验证用的诊断内存读取。采集为一个接口样本。底层使用实际 Electron nativeImage 和实际 GlobalAlloc/GlobalLock/RtlMoveMemory/GlobalFree，剪贴板读、打开、清空和提交为适配器；没有访问系统剪贴板。

这不是全应用内存、真实粘贴延迟或全部硬件负载的测试。同步 PNG 校验/解码、既有 DIB 完整校验、输入字符串、生成位图、Windows 所有权转交和其他路径仍有开销；不能把分块 Buffer 指标解释为总内存只用 192 KiB。没有新增持续驻留的图像进程；API 探测表明本机 Electron 工具进程没有 nativeImage，未使用未公开绑定。

339 项逻辑回归、类型及语言检查通过，新增十项原生准备/容量测试和两项采集/编辑服务测试。实际 Windows 私有内存与图像样本比对 PNG、DIBV5 像素、私有格式原字节及所有权清理；准备中取消不打开剪贴板，随后可再次准备。界面 120 项、媒体反馈 48 项及基础组件 16 项比对的本轮结果见交付报告；完整 348 布局、通知和动效沿用 0.32/0.31 的既有证据，不计作本轮重测。

核心适配测试与私有内存测试没有真实 OLE、物理键鼠、系统剪贴板、真实截图、双机同步、干净 Windows 或受控驻留内存测量。没有签名或公开发布。原项目、One 参考仓库和以前交付均保持不变。

异步内存调用与指针运算依据现有依赖的 [Koffi 异步调用说明](https://koffi.dev/load#asynchronous-calls) 和 [指针说明](https://koffi.dev/pointers)，没有升级依赖。

0.33.1 修正并验证了混合格式数量上限：32 种原始格式可与文字、HTML、RTF、PNG 和自动生成的 DIBV5 共存，共 37 个格式块。单条和总字节限制保持不变。上表保留 0.33 的七次测量，未将补丁测试的新时序替换成新的性能结论。
