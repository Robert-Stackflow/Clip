# Clipper 0.40.0

运行 `Clipper-0.40.0-win-x64/Clipper.exe`，保留整个程序目录。先从旧版托盘退出，再打开这一版。

修复了十个窗口的公共样式资源加载：此前页面链接了 one-ui.css，但四处原生资源白名单遗漏了它。现在共用严格的资源清单，主窗口、图片编辑、录制和长截图均允许此文件，同时保留窗口隔离和路径限制。实际原生加载检查会验证样式表规则及搜索输入框的边框，不能再仅凭 HTML 链接判断加载成功。

这轮继续迁移 One 的实际实现：采用 `src/renderer/window-visibility.ts` 的原生窗口可见性控制，隐藏、最小化和预热窗口不再持续加载图片或全文预览。十个入口继续使用 0.39 已核对的共用组件、布局和样式；本轮没有重新绘制这些组件。One 同期源码已更新到 0.16.12，其中基础样式、下拉菜单和字体选择器有新增变化，已记录于 ONE-UI-REVIEW-0.40.json；这些差异还需继续逐项核对，本轮不宣称已迁移到其最新样式。

主窗口和快速粘贴窗口隐藏时，会撤销所属窗口的图片资源租约、取消搜索、移除图片解码对象，并销毁全文阅读器和后台 worker。阅读器模块尚未加载或 worker 尚未完成时，也能取消；晚到的图片响应会立即释放。重新打开时读取最新原件，保留当前记录、查找词、文字选择、换行、代码折叠和阅读位置。阅读位置使用 CodeMirror 的锚点快照，避免长文档高度估算变化造成跳位。

预览的释放不重建设置表单，也不关闭编辑 dialog。未保存设置、输入内容及正在编辑的草稿继续保留；正文变更后，旧阅读快照会失效。外部待处理任务只在窗口可见时开始领取，已经接受的任务仍按原流程完成。

验证覆盖 381 项逻辑测试、151 个文件的语言绑定检查、348 项页面布局、120 项组件与页面操作、16 项全文阅读、24 项跨页面搜索、20 项表单与确认、4 项动画及 12 项异步操作。另有 10 个页面通过原生资源清单加载公共样式的检查、14 项窗口资源行为、7 项原生状态/沙箱预加载/所属窗口资源撤销、3 项慢模块及 worker 取消检查。打包验收使用实际 ASAR 中的主界面、全文阅读器、worker 和预加载；既有图片保存、加密数据库、恢复、字体、剪贴板格式及 0.27 功能继续检查。

三轮交替对比使用相同 Electron 44.5.1 和私有测试窗口。4096×4096 图片在 0.39 隐藏后仍有 64 MiB 活跃解码缓存，0.40 降为 0。约 79 万字符的全文阅读器隐藏后，0.40 的 JavaScript 堆减少约 1.7 MiB，0.39 基本保持。原始数据及每次测量条件记录在交付校验 JSON 的 `work/visibility-040/results.json` 中。

这是渲染进程的受控样本：两版都显式触发 GC，窗口物理上始终隐藏，以所属窗口状态信号模拟显示/隐藏。工作集和专用内存没有按解码缓存量等幅下降，不能据此推断完整应用即时回收 64 MiB。日常 One 0.15.2 的只读进程记录也保留在交付校验中；它的版本、窗口数、工作负载不同，不用于判断新版 Clipper 更快或更省内存。

本轮未使用用户键鼠、系统剪贴板或日常资料。真实桌面的显示/最小化、DWM 像素、完整应用驻留内存、两台设备交互和实际应用粘贴仍不在本轮验证范围。程序未签名，也未发布到 GitHub。临时测试目录因自动审批拒绝清理而保留，不影响运行目录。

构建与交付使用独立依赖和冻结源码，核对源码、实际 ASAR、十个页面的公共样式入口及程序文件。验收后，将本轮构建的完整程序目录移交到输出目录并再次逐文件核验；没有改变之前已交付的版本。
