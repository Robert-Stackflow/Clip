# v0.17 堆栈自动入栈与批量规则验收

2026-10-01，Windows 11 x64、Electron 44.5.1、两块屏幕分别为 150% 与 125% 缩放。真实桌面测试使用隔离资料目录并串行运行，结束恢复支持的原剪贴板内容。

## 覆盖范围

默认停止；开始不补采原剪贴板，只收集后续外部复制。真实文字按顺序入栈、重复保持首次位置、本应用复制不回流；来源名称与包含词同时匹配，按行拆分为纯文本，空行和重复处理，图片在按行模式下跳过。批量预览不写入，确认追加、反转队列、清空确认和真实 Windows 下一项快捷键粘贴成功后出队。浅色、深色和紧凑主窗口检查。

规则参数和伪造令牌被拒绝。暂停/恢复、排除应用变化、隐私标记、模拟休眠不补采；停止后迟到的实际剪贴板读取可按正常历史规则保存，但不能入栈。实际存储迁移及数据库加密、锁定、密码解锁保持本机规则，取消运行状态和确认令牌。重启保持队列与规则，收集恢复为停止。

逻辑和真实数据库测试覆盖精确来源匹配、类型与关键词、CR/LF 拆分、空白选项、200 项容量、全部拒绝而不截断、SQL 中途失败整体回滚、确认期限、来源/队列变更、私密派生条目和重复隐私、加密存储与普通备份排除。新行和跨条重复均计入预览的重复数。队列仍按内容去重，不保存重复副本；不会覆盖普通 Ctrl+V。

## 限制与后续

剪贴板采样沿用既有约 350 ms 轮询；非常快的连续复制可能只读到最后内容。来源依据剪贴板所有者进程，代理或远程桌面可能影响归属。规则按 AND 字面匹配，不执行表达式；批量预览按已存在的历史快照展示，后续新记录需重新预览。队列最多 200 项，批量历史预检最多 10,000 条；超过限制需调整规则或减少历史。

IPC 自动化与模拟系统事件不等同于物理休眠、多屏、Office/邮件应用的真人验收。目录包未签名，安装更新、虚拟文件夹、更多私有格式、中英界面和实际设备兼容性继续按完整开发计划推进。本版不声称已经完成 OneClip 全部功能对齐。

自动粘贴以 Windows 接受按键注入为完成依据，不能确认任意目标应用实际插入了内容。输入法组字或同时输入可能拦截粘贴，即使系统接受注入并且队列已移出；原始内容仍在历史中，可重新入栈或手动粘贴。

## 本轮混合缩放检查

当前枚举到两块屏幕（150% 与 125%）。首次 capture 测试把显示器外部 DIP 宽度当作选区页面内容宽度，第一块屏幕在坐标换算中分别为 1708 与 1707，触发断言。Win32 窗口物理矩形、Electron 外框/内容矩形及 renderer 视口诊断确认：全屏覆盖正确，程序已有裁剪使用实际内容矩形，区域像素对照通过。修正夹具为核对全屏外框等于目标显示器、视口等于实际内容矩形，继续严格检查裁剪尺寸、左右像素、取消和隔离预加载；未改动应用或放宽像素断言。诊断在 work/capture-dpi-diagnostic-0.17.log，原失败日志保留。两块当前屏幕的检查不替代所有混合 DPI、热插拔与物理设备验收。

手动“按行拆分到堆栈”也共用事务与隐私处理，继承来源的仅本机标记；相同文本已共享时整批拒绝，原队列与历史保持。旧实现未继承该标记，本版同时修复，并以专门数据库用例及发布包检查覆盖。

桌面停靠测试在多屏环境中还暴露出夹具默认位置假设：测试将鼠标移到配置屏幕边缘，但全屏测试来源未显式放在该屏幕。修正为将受控窗口移至目标显示器后全屏，核对其实际边界，再验证全屏抑制；抑制断言保持。

长截图两组夹具也默认选中列表第一块显示器，而受控内容位于主屏；UI 用例还把滚动距离与取样行位置固定为 150% 缩放。当前主屏为 125%，显式选择其 ID，并按该屏比例计算期望值后，600×450 初始区域、两次各 150 DIP 滚动后的 600×825 拼图及原始逐行颜色对照通过。边界夹具同样改为每次打开选择受控窗口所在屏幕，保留取消、窄图预览和生命周期断言。应用长截图实现未改动；原失败记录保留。

迁移停止修复前的候选构建首次 stack-ui 原生下一项快捷键检查未收到目标输入；没有改动程序或输入步骤，仅增加失败时焦点/注册状态诊断后，该候选构建专项复测通过。首次日志保留，具体瞬时原因未确认；最终构建重新从第一组验证，不沿用旧构建结果，也不把受控目标的通过结果外推为所有前台应用可靠性。

界面复核：浅色收集与批量预览、深色规则窗口已检查；860×600 主窗口工具栏未溢出。该最小高度下详情正文区域偏小，建议增加窗口高度查看长内容，后续继续优化紧凑布局。

迁移并发检查另外覆盖资料库已关闭而新库尚未交接的阶段：受控延迟迁移标记清理，期间立即停止收集及触发模拟休眠/恢复，确认不访问已关闭数据库、不恢复旧会话。托盘使用内存运行状态，切换期间延后界面广播。

旧测试目录的 app.asar 在测试进程退出后仍被外部文件占用，两次覆盖打包失败；保留该目录，改以同一源码/构建输出打包至 release/0.17.0-final/win-unpacked，不强制终止未知占用者。最终验证与交付均以这个新目录为准。

该新构建的基础粘贴检查连续两次收到脚本未发送的字母/空格，以及输入法 Process 按键事件；剪贴板内容相符、队列已前进，但目标框未插入期望内容。两次失败结果和事件诊断均保留；测试未关闭或修改系统输入法，也未放宽目标内容断言。随后暂停需要前台键鼠的回归，等待桌面可独占操作时继续。

用户明确暂时停用键鼠后，同一程序与未修改的基础粘贴测试通过，并继续后续套件。额外输入与前两次失败同时出现；未证明所有输入法状态下的兼容性。
