# 启动、应用图标与开机托盘驻留

2026-10-08。此记录对应当前源码修复，尚未重新生成安装器；既有 0.50.19 安装包不包含本轮变更。

## 问题与修复

- 正常启动曾逐条验证历史正文并计算整个数据库指纹。已识别资料在同版本启动时改为只读检查资料编号、主表结构及数据库版本；导入、恢复和版本变化仍执行完整校验。更新服务初始化与资料打开并行进行。
- 本机 Windows 启动项仍指向已不存在的 `release/0.46.0/win-unpacked/Clipper.exe`。正式安装版正常启动时会按已保存的设置更新固定启动项，使用当前程序路径及 `--startup` 参数。设置页和托盘开关使用同一实现，开发和测试实例不写入正式启动项。
- 开机启动只驻留托盘，普通启动显示主窗口。再次收到开机启动请求仍保持隐藏，托盘点击或手动启动可显示窗口；手动重启清除开机启动参数。尚在初始化时的打开请求保留到窗口就绪。
- 加密资料的解锁窗口，以及资料异常时的恢复窗口，在开机启动时保持隐藏；点击托盘后再显示。
- 应用图标的失败结果不再永久缓存；刷新已观察到的程序路径以处理 Windows Store 应用更新。图标采用原子写入的本地缓存，最多 256 个、每个不超过 128 KiB。旧版本目录消失且应用未运行时，可继续使用已成功读取的图标。前端对暂时失败的应用图标进行有限次数重试。

## 验证

- 631 项核心测试、类型检查、构建与语言绑定检查通过。
- 当前约 259 MiB 的资料只读测量：完整检查约 1,592 ms，启动元数据检查约 15 ms。这是检查步骤的测量，不代表整个软件启动耗时。
- 21.6 MB 合成历史的测试确认普通启动使用紧凑元数据路径，升级仍拒绝损坏的记录正文；同时检查错误资料编号、未来数据库版本及缺失主表。
- 隔离 Electron 实例验证普通启动、开机启动、加密资料开机启动及恢复资料开机启动。最后一轮测得窗口和页面就绪约 0.5–0.9 秒；较早一次冷启动约 3.3 秒，不能作为所有设备的速度保证。资料暂停捕获，六类全局快捷键清空，关闭 Win+V 拦截。
- 使用实际 Windows 注册接口验证旧启动路径替换、启用状态、注册表中的托盘参数及关闭后移除。只操作随机命名的测试启动项，测试后清理；未重启 Windows，也未替换正在运行的正式版。
- 使用正式版资源目录布局和实际 SourceHost 读取当前 Windows Store 版 ChatGPT 图标，确认 128×128 PNG。验证暂时失败重试、旧路径刷新及应用关闭后缓存恢复。
- 实际沙盒应用的退出重启、资料保留及托盘重启路径通过。

测试日志保存在 `work/current/startup-*.log`，窗口行为报告保存在 `work/current/startup-electron/startup.json`。这些证据不替代干净系统的安装与实际重启验收。
