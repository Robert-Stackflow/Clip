# 快捷面板焦点与光标定位（2026-10-08）

快捷面板弹出时使用不激活窗口的方式，保留原应用的前台窗口和输入控件焦点。点击搜索或表单输入框、填写快捷回复变量时才激活面板；粘贴仍使用打开前捕获的窗口和输入控件。面板不会通过关闭开始菜单来获取焦点。

光标定位依次使用 Win32、MSAA 和 UI Automation，允许现代输入控件由其他进程承载。辅助进程只读取几何位置，不读取输入内容；查询和重试都有时间上限。Chromium 首次启用辅助功能但尚未返回位置时允许一次短重试。无法读取位置时使用当前窗口右下角。

已在隔离资料和禁用全局快捷键的 Electron 测试中验证：

- Clipper 输入框中的最近记录、快捷面板记录和快捷回复粘贴。
- 外部 Electron 输入框的记录、快捷回复粘贴，以及点击搜索后恢复原输入点。
- 弹出面板时原窗口保持前台，点击外部区域关闭面板。
- 空 Chromium 文本框的 MSAA 光标位置，Windows 开始菜单搜索框的 UIA 光标位置。
- 录制状态允许唤出面板，粘贴保留录制控制窗口。此项使用模拟录制状态，没有进行真实视频录制。
- 拖动面板保持尺寸，不随按住鼠标而增长。

测试输出位于 `work/current/quick-paste-electron/result.json` 和对应的构建、核心测试日志。测试使用私有剪贴板标记并恢复之前的剪贴板内容。

## 尚未解决

Windows 开始菜单、搜索面板具有高于普通桌面置顶窗口的系统窗口层级。实际命中测试确认：即使面板保持置顶并保留搜索框焦点，重叠部分仍被系统面板遮挡。改变置顶级别或设置窗口 owner 均不能作为已解决的依据；未保留无效的 owner 修改和关闭开始菜单的替代行为。

没有找到微软公开的 Win+V 面板实现源码。公开的剪贴板历史 API 不包含该面板的窗口层级和输入路由实现。UIAccess 需要受信任的签名、安装位置等条件，微软也明确不应仅为覆盖系统界面而使用它。
