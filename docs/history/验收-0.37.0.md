# Clipper 0.37.0

从旧版托盘退出后，运行完整目录中的 Clipper.exe。无需安装，移动时保留整个目录。

本轮重点是大附件堆栈和恢复响应。沿用已经迁移的 One 组件、设置布局和页面骨架；本轮再次用本机 One 的实际 styles.css、components.css、segments.ts 对照基础控件。没有把沿用页面表述为重新设计。

- 恢复堆栈/拖放容器、队列重排和存在性检查只查记录 ID。
- 自动入栈去重、预览有效性和文件共享有效性只读记录身份与隐私标志，避免反复解析原件。
- 批量入栈按类型/来源先筛选，再读取文本与文件信息。整条模式的待确认状态只保存 ID、哈希、隐私状态和简短样本，不保留图片、附件或私有格式正文。按行模式继续保存生成的纯文本。
- 确认前仍校验队列、规则、内容哈希和共享/隐私状态；变化、删除、取消或到期使预览失效。整条复制、粘贴、同步、导出继续使用数据库中的完整原件。
- 附件和格式的缓存字节数用有效 base64 的 ASCII 字节长度计算，减少重复字符扫描。0.36 触发器在事务内替换；缓存内容、模板版本计数、原始记录、备份格式和 user_version=7 保持兼容。首次补建和写入仍有开销。
- 构建时清理确认位于当前工作目录内的生成全文阅读资源，拒绝链接/越界目标，避免多次构建积累旧分块文件。用插入的过期资源验证其移除，最终保留 125 个阅读资源。

原始记录逐字节一致，原始历史容量计算仍为 83,887,824 字节。全部保存耗时保留在报告中，仍有波动；本轮没有声称大附件入库已达到上述队列操作的毫秒耗时。

性能数据是独立私有 Node/SQLite 进程中，交替执行固定的 0.36 源码和当前源码所得。样本为 3 条各 10 MiB 附件、3 个附件回复和 200 个重复队列位置，保留每次保存、重开、预览、确认、内存和字节样本。最终复测期间没有同时运行本任务的构建或其他回归。机器其他后台活动可能影响耗时。这不代表整款应用的启动耗时、峰值或驻留内存，也不是实际系统剪贴板/两台设备测试。GC 后 heapUsed 只衡量私有测试进程中的堆变化；没有声称所有大文件写入都更快。

复现：tests/performance-037.cjs；对照依赖独立保存的 delivery-0.36.0。旧缓存触发器的实际源码作为 tests/fixtures/preview-index-036.ts 随源码提供，所以常规逻辑回归不依赖旧版目录。

验证：357 项核心逻辑、类型检查、148 个语言绑定文件（缺失/未绑定均为 0）；120 项页面控件、16 项搜索、16 项当前 One 基础控件样式对比、48 项媒体反馈、16 组全文阅读、47 项异步操作、4 组动效和 4 组图片预览专项通过。新增 4 组中英/明暗堆栈界面验证直接接入实际 Store/Stack，检查自有 dialog 的预览、确认、隐私变化阻止提交、取消释放、原件保真和横向布局。其桥接是私有浏览器 binding，不冒充真实 Electron IPC。

实际 ASAR 和隐藏 Electron 验证预览 worker、sandbox preload、生产 renderer/CSP、加密原图、原始字节/像素、窗口归属与释放；保留加密恢复、同步文件 worker、Rust Office/PDF、重复堆栈、搜索、字体、图片导出和 37 种格式内存块验证。新增 8 项性能逻辑在打包 EXE 的 Node 模式下，用同源生产核心和实际 ASAR 依赖再次执行，包括加密重开及 0.36 缓存触发器升级。完整程序与源码逐文件核对。完整旧版 348 项布局基线沿用已有结果，不计为本轮重测。

所有验证使用私有样本、无头浏览器或隐藏窗口，没有使用系统剪贴板、物理键鼠或日常资料。完整主程序启动、真实 OLE 拖放、物理两台设备、DWM 像素和全应用受控驻留内存未复测。程序未签名、未公开发布。
