# 0.49.7 最近记录按需读取正文

最近记录搜索先核对名称、来源和标签；这些字段满足全部搜索词时，不读取长正文。仍需正文的搜索词或基于内容的分类才读取已有预览缓存。保留更新时间与 ID 排序、精确总数、最多 80 条摘要、原有 Unicode 匹配规则、旧数据库投影和缺失预览缓存时的内连接行为。原图片、附件和富文本正文不进入搜索结果。

501 项核心回归、类型与 2,246 条自有语言字符串检查通过。新增明文/加密用例验证 93 条长文本按来源、标签或名称搜索时读取正文为零，混合正文与标签搜索和内容分类仍读取需要的正文；通过独立完整记录结果验证精确身份、顺序、总数和分类，工作线程结果相同，主记录字节不变。既有四种明文/加密与有缓存/旧数据库组合继续通过。

## 独立读取进程

固定 0.49.6 的提交 4c3644f 中的读取器作为旧版，正式新代码作为新版；相同生成资料、每版独立进程。明文/加密、同时间/不同时间、正文/元数据搜索各三轮，共 48 个样本，每份含 1,500 条约 7,400 万字符长文本。前 80 条身份使用独立 SQL 验证，数据库仅供读取。没有强制 GC 或调整工作集。

| 场景 | 来源与标签搜索旧版→新版（中位数） | 正文与标签搜索旧版→新版（中位数） |
| --- | --- | --- |
| 明文，不同时间 | 320.0→13.6 ms | 318.0→298.6 ms |
| 明文，同时间 | 325.4→12.1 ms | 322.1→369.8 ms |
| 加密，不同时间 | 504.0→15.5 ms | 505.4→470.3 ms |
| 加密，同时间 | 539.0→14.9 ms | 512.0→496.9 ms |

来源与标签搜索的明文读取进程峰值约 81.0→60.0 MiB，加密约 97.4→61.4 MiB；这是独立读取进程，不能作为全应用峰值。明文同时间正文搜索有变慢样本，不能声称所有正文场景都已提速。报告为 work/current/recent-search-scan-profile-implementation/result.json。

此前分别比较过不排序全部扫描并维护前 80 条、强制按表扫描两种方案，共 48 个原型样本，没有显示稳定收益，未加入生产代码。对照脚本 tests/recent-search-scan-profile.cjs 保留固定旧读取器版本与原型开关，避免把旧、新结果混为一组。

## 发布运行时验证

0.49.6/0.49.7 真实目录包各三轮、每轮明文/加密与正文/元数据搜索四组，共 24 个样本。每个查询使用包内实际 Electron 工作线程，包含启动、读取、返回和终止的等待，版本由 app.getVersion 核对。隔离生成资料含 1,500 条同时间长文本；独立 SQL 核对前 80 条身份与精确计数，读取前后数据库 SHA-256 相同。

该测量明确保持界面隐藏，不模拟前台键鼠或改变失焦保护；不会替代未完成的前台界面、取消重开和锁定整条流程验收。250 ms 的全应用工作集采样无法捕获 48–67 ms 短查询的完整峰值，因此元数据样本中的零采样增量不能解释为零内存占用，也不用于宣称全应用峰值改善。报告为 work/current/recent-search-packaged-worker-0497/result.json。
