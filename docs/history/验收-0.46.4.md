# 0.46.4 大图编辑开销优化

## 实现

新增编辑和重做只绘制当前一步，撤销仍重放完整操作列表。主画布与导出保留原图像素；透明选区层按屏幕显示大小分配，动画位图按显示大小、DPI 和动画终点分配且最多 400 万像素。操作列表序列化移出拖动和状态刷新路径。

## 验证

- 301 次混合编辑、撤销、重做的像素比较，以及 32 种预览尺寸边界检查通过。频繁读像素的对照画布使用相同 CPU 后端，另有默认画布后端的整段混合编辑比较。
- 4000 × 3000 的生产界面完成 20 次旋转/翻转，最终 PNG 和撤销后的 PNG 与固定 0.46.3 基线一致；导出和恢复到已保存步骤的状态检查通过。
- 18 组媒体交互、48 组媒体布局检查通过；覆盖中英、深浅主题、适应窗口/100%/200% 下的实色遮盖坐标、动画裁切、窗口改变与减少动态效果。

性能对照和实际运行进程采样见 `work/current/image-edit-performance`。浏览器场景为独立无头 Edge、1.25 DPI、同一 1,200 万像素合成图、20 次操作、三轮交替次序；不操作系统剪贴板或实体录制设备。动画帧时间截止于下一次 requestAnimationFrame 回调，不代表物理屏幕的绘制延迟。进程内存采样于暂停的动画期间，不代表完整生命周期峰值。

最终三轮记录（固定基线提交 `dba3485`）：

| 测量项 | 0.46.3 基线 | 优化后 |
| --- | ---: | ---: |
| 20 次操作的主画布 drawImage 调用 | 230 | 20 |
| 临时动画位图 RGBA 尺寸估算 | 45.8 MiB | 3.9 MiB |
| 所观察画布的峰值 RGBA 尺寸估算 | 198.4 MiB | 112.8 MiB |
| 操作处理时间中位数 | 3.0 ms | 2.5 ms |
| 第 20 步处理时间中位数 | 4.2 ms | 3.4 ms |
| 下一帧回调时间中位数 | 4.9 ms | 3.4 ms |
| 动画期间进程私有内存中位数 | 910.1 MiB | 879.4 MiB |

位图分配估算下降约 43%；进程私有内存最后三轮下降约 31 MiB，图形进程缓存存在波动，不能将估算的位图差值直接当作整体内存下降。新增步骤仍受原图尺寸上限限制，撤销会重放历史列表；长期驻留和物理屏幕帧时间继续跟踪。

实际 One 与 Clipper 均为正在运行的开发实例，窗口数量、运行时间和工作负载不同。记录其私有内存及工作集供后续排查；工作集包含共享页面，不能据此评价两款产品的效率。

最终只读采样（具体时间、进程身份和角色见目录包旁的 `resident-apps.json`）：One 为 6 个进程、349.1 MiB 私有内存、535.5 MiB 工作集；Clipper 为 4 个进程、250.3 MiB 私有内存、362.8 MiB 工作集。这是现有开发会话的瞬时观察，不是相同空闲条件下的测量。

## 交付

`release/0.46.4/win-unpacked/Clipper.exe` 及完整目录已经生成。194 个编译文件与目录包匹配，性能报告中的图片界面 SHA-256 与打包界面相同；包内 SQLite、Koffi 和 QuickJS 的 Node 模式检查通过。`verified-build.json`、`image-performance.json` 记录具体范围，此验证不代表发布包窗口启动或完整实机验收。
