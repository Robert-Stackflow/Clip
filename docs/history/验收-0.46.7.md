# 0.46.7 大内容同步接收

## 改动

超过 64 KiB 的同步正文在短期工作线程中解析、校验、计算摘要及写入 SQLite。接收字节使用独立缓冲区直接转移，完整正文不回传主进程；提交后只返回记录身份和隐私变更通知。共享标记和正文合并为一次保存，避免同一大字符串重复序列化、索引和落库。短内容保留即时路径；主动推送与拉取共用接收处理。

从读取网络正文、准备至提交完成最多占用两个接收槽位。工作线程准备结束后进入现有串行写入队列，事务中重新检查重复项、仅本机内容及本机保留权。正文、共享索引和缓存原子提交，失败回滚。配对信任更新及取消也经过同一队列，避免与后台写事务争抢数据库连接。取消在提交决定前生效；事务已接受时，停止等待原子提交完成，再释放连接和线程。关闭同步、撤销信任、锁定或切换资料使等待中的任务失效。密钥副本与接收缓冲区在移交或结束后清零，没有增加生产环境明文暂存文件、协议版本、数据库格式或依赖。

PNG 缩略图仍通过主进程的现有原生解码器生成，传回的 PNG 必须先通过校验和摘要匹配。删除标记仍由主进程连接处理，保留删除撤销、队列和拖放架状态。因此本次没有宣称消除所有同步工作中的主进程耗时。

## 验证

完整核心 **439 项**与类型检查通过。新增接收回归 10 组，使用真实工作线程和明文/加密数据库，覆盖原始格式及附件逐字节一致、轻量通知、幂等重试、本机保留权、收藏/置顶/标签、仅本机、远端撤回、错误密钥、容量与协议失败回滚、超时、最多两个任务、排队取消、有效 PNG 缩略图及删除撤销；另验证提交决定后的停止等待完成。文件数据库 TLS 回归实际拉取 10 MiB、推送 2 MiB 附件，并禁止发送及接收端主连接读取大原件；撤销与拥塞用真实 TLS 接收请求验证。配对取消的 TLS 回归确认它排在已入队接收后执行，已接受的内容保持完整，随后撤销配对信任。

目录包 Electron 44.5.1 / Node 24.21.0 实际加载包内新工作线程，向加密历史写入 3 MiB 原始格式。重新打开数据库后正文逐字节一致、共享记录及同步目录同时存在，重复接收没有新增记录；线程已退出。检查只使用隔离合成资料，不接触系统剪贴板、键鼠输入或启动桌面界面。

双语静态覆盖检查为 2,191 条来源消息，缺失与未绑定列表为空。目录包源码归档、原生数据库/Koffi/QuickJS 和文档一致性结果记录在交付校验 JSON；不将这些结果视为全部应用界面或 Windows 兼容性验收。

## 性能对照

固定基线为 `cada335`（0.46.6）的接收 SyncLedger 实现，与当前 Store 的默认保存路径组合；当前方案启用工作线程和一次保存。使用相同合成 10 MiB 附件、每轮独立 SQLite 文件与进程，五轮交替测量。正文已在内存中，范围包含 JSON 解析、校验、摘要、重复检查、写入及索引、线程退出，不包含 TLS 获取、PNG 缩略图解码和 UI。两种运行时分别计算中位数。

| 目录包 Electron / Node 24 中位指标 | 基线 | 当前 |
| --- | ---: | ---: |
| 主进程事件循环最大超时 | 520.60 ms | 13.16 ms |
| 接收处理完成 | 523.49 ms | 401.99 ms |
| 主进程堆增长 | 40.14 MiB | 0.42 MiB |
| Windows 进程峰值工作集（含线程） | 418.70 MiB | 402.07 MiB |

系统 Node 22 的中位事件循环超时为 595.81 → 13.02 ms，完成耗时 598.64 → 379.34 ms，主进程堆增长 53.50 → 0.26 MiB，峰值工作集 406.64 → 405.62 MiB。原始报告分别保存在 `work/current/sync-receive-performance-electron/result.json` 与 `work/current/sync-receive-performance/result.json`。

峰值使用 Windows PeakWorkingSet64，从测试子进程读取，包含工作线程与进程启动，在正文一致性复核前取值。它不依赖被阻塞的主进程采样器；报告仍保留主进程定时采样值供区分。线程退出后的 RSS 是隔离任务观测，不能证明应用长期驻留内存改善。当前主要收益是降低主进程停顿和重复保存；总进程峰值内存没有数量级改善。
