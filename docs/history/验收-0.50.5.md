# 0.50.5 原窗口粘贴顺序验收

2026-10-04。此前真实记事本试用中，最近记录先隐藏自身窗口，再请求 Windows 恢复原目标；这一顺序可能使前台切换被拒绝。现在写入剪贴板后，Clipper 趁最近记录窗口仍在前台时请求切回目标，再隐藏自身窗口；等待修饰键松开、确认目标确实在前台且会话仍有效后，才发送 Ctrl+V。目标切换失败时仍显示已复制及手动 Ctrl+V 的回退提示。

使用独立测试资料，`node tests/paste-native.cjs` 在普通 WinForms 目标窗口完成自动粘贴；`node tests/paste-notepad.cjs` 在实际系统记事本完成自动粘贴并从记事本复制回读相同文本。测试夹具会恢复其保存的剪贴板格式；运行记事本测试前要求没有其他记事本进程。最近记录界面与边界回归、类型检查通过。

追加真实应用验收：`node tests/paste-word.cjs` 在全新空白 Word 文档读回粘贴的纯文本，`node tests/paste-excel.cjs` 在全新空白 Excel 工作簿的 A1 单元格读回相同文本；0.50.5 包内程序的两项测试也通过。测试要求对应 Office 应用原本未运行，结束时放弃保存临时文档与工作簿。

Windows x64 目录包位于 `release/0.50.5/win-unpacked`。打包检查确认 260 项资源与源码一致；实际 `Clipper.exe` 使用独立暂停自动记录的资料启动，主界面、样式和原生组件正常，截图已目视核对。包内程序分别通过原生目标和记事本粘贴测试；验收脚本确认 `app.asar` 与原生附件组件的哈希在测试前后未变。dev 继续运行。

本次证明这台机器上的记事本、Word 和 Excel 等受控目标的纯文本粘贴可用，不代表富文本、文件、管理员权限窗口、不同输入法和多屏场景都已通过。目录包未签名，正式发布链路与双物理设备仍未验收；整体目标继续进行。性能与录音录屏性能调查按此前用户要求保持收尾状态。

后续补充：`node tests/paste-word-rich.cjs` 使用隔离资料和全新 Word 文档，分别验证普通粘贴及指定 RTF、HTML 格式粘贴。源码程序与现有 0.50.5 目录包均通过；RTF 和 HTML 中的粗体、颜色 `#d7263d` 与 18pt 字号得到保留，测试结束未保存文档并恢复原剪贴板。此机 Word 的外部来源普通粘贴偏好为“匹配目标格式”，普通 Ctrl+V 因此显示目标文档的黑色、11pt；测试未修改 Word 偏好。该补充只覆盖受控 Word 目标与构造的富文本样本，不扩展到其他来源应用或文件格式。

文件回贴补充：`node tests/paste-explorer.cjs` 从独立文件来源捕获 CF_HDROP 条目，再经最近记录粘贴到本机资源管理器打开的独立空目录。源码程序和现有 0.50.5 目录包均通过：先验证单文件逐字节一致，再验证“文件 + 文件夹”组合中的二进制文件、嵌套文件和空目录均落入目标目录；源文件保持不变，前台返回资源管理器。随后由独立原生 OLE 进程提供 IStream 虚拟附件；Clipper 完成捕获且来源进程退出后，最近记录仍把相同字节的附件粘贴成资源管理器中的文件。测试正确处理最近记录窗口闲置销毁后的重新打开，并在每次粘贴前确认资源管理器是目标；目录包连续三次、源码程序一次通过。测试只关闭自己新打开的资源管理器窗口，不触及既有窗口。这证明本机受控文件、目录及构造的虚拟附件场景，不代表 Outlook 实际邮件或其他复杂来源已验收。
