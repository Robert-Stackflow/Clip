# 0.49.3 最近记录后台搜索

最近记录的文字搜索、收藏与分类筛选移至一个短期只读工作线程，使用一致的数据库快照。默认打开仍从摘要索引读取最近 80 项；搜索扫描完整文字、文件名、来源与标签，返回最多 80 项和准确总数，不传递原图片或附件内容。

新查询先取消旧查询并等待线程结束；窗口关闭、资料切换、锁定与退出撤销旧结果及操作凭据。主进程只为当前会话结果签发新的复制、粘贴和预览凭据，执行时继续校验记录身份。工作线程结束前关闭数据库，加密密钥副本用后清除，没有新增常驻线程池。

保持 0.49.2 已验收的资料页间距和字体回收行为。本轮不继续调查录音录屏性能。

491 项核心回归、TypeScript 与语言覆盖检查通过。回归覆盖明文和加密历史、超过预览长度的 Unicode 正文、来源与标签、文件名、精确总数、80 项上限、不存在的分类、失败与超时、取消后重试、关闭/重开/替换查询/切换资料后的迟到结果、旧操作凭据失效以及原附件内容保持。存储切换检查确认等待最近记录查询停止后才执行资料切换。

两个发布包各五轮交替启动独立进程，使用同一份隔离资料：1,500 条约 47,104 字正文、一份附件和一张图片。主窗口列表出现并等待 1 秒后测量。搜索词同时匹配完整正文、Unicode 大小写与标签；默认显示最近 80 项，收藏筛选精确为 500 项，自定义文件分类可正确预览，关闭正在进行的搜索后重新打开时恢复默认查询。原 PNG 与附件字节校验保持一致。

Windows 前台窗口切回 Codex 时，最近记录会按失去焦点规则关闭。早期连续测量因此失败，未列入下面结果。正式测量拆成每次一对程序的短轮次，在本轮结束后才报告；测试授予自己的窗口实际焦点，鼠标位置与置顶状态随后恢复，没有关闭产品的失焦保护。搜索计时从设置搜索框前开始，排除授予焦点的等待。

以下为五轮中位数。搜索时间包含 180 ms 输入等待、查询及计数显示；主窗口请求包含自动化传输与 IPC，主进程最大间隔来自 5 ms 计时器，不能等同真实硬件输入延迟。每 250 ms 读取本次应用进程树工作集，没有测量全机内存，也没有强制 GC。

主窗口响应明显改善，但搜索等待增加约 278 ms。新版本峰值增量范围为 184.1–309.1 MiB，旧版为 200.3–234.8 MiB；新版本有一轮更高，不能将中位数略低描述成整体峰值或长期驻留已解决。工作线程启动与完整正文扫描的总等待，以及应用整体内存仍待优化。

另外在实际发布程序中将同一份样本启用历史加密，核对磁盘数据库不是明文 SQLite，再进行完整搜索、分类、关闭重开及原内容校验。单轮搜索约 4,072 ms，最慢主窗口请求 33 ms；查询期间锁定后约 539 ms 显示锁定界面，最近记录窗口销毁。该单轮没有加密历史的旧版对照，不能推断加密搜索速度改善，完整扫描等待仍需优化。

只读采样现有开发会话时，One 进程树工作集约 995.8 MiB，其中 One.Index.exe 约 906 MiB；Clipper 当前开发会话约 211 MiB。One 包含已运行较久的文件索引，和 Clipper 的功能、资料及运行时长不同；该快照仅作为现有会话驻留参考，不构成公平的内存对照，也未修改 One 的进程或数据。
