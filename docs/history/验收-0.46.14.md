# 0.46.14 大量快捷回复导入去重

## 改动

备份导入原来对每条快捷回复重新遍历已有列表，并重复序列化参与比较的内容。本版将既有内容的标题与正文身份在事务中建立一次集合，导入时只判断一次，保留相同内容不重复导入的行为。0.46.13 的容量增量计算继续有效。

## 检查

核心测试 455 项、TypeScript 类型检查和语言绑定检查通过。新增回归使用允许的最多 2,000 条快捷回复，混合已有内容和备份内重复内容，重复导入后仍只有 1,999 条，并且只为实际新增的 1,998 条生成缩略图。0.46.14 实际打包程序使用独立临时资料连续两次恢复 2,000 条快捷回复，第二次没有增加重复项；包内 199 个构建文件与源码构建结果一致。

相同 2,000 条合成文字快捷回复，在独立 Node/内存 SQLite 进程中交替测量三轮：0.46.13 为 460、487、491 毫秒；本版为 408、398、418 毫秒。每轮写入 2,000 条，数据库容量均为 642,670 字节。此对照只覆盖导入算法，不代表完整界面响应、磁盘写入或内存峰值。

## 限制

备份预览、解码和最终恢复仍在主进程；较大的备份仍可能造成窗口停顿。工作线程写入需保留同步变更通知、资料缓存和事务一致性，本版未绕过这些约束。上述实际打包测试使用未加密的合成备份；真实大型加密备份、磁盘数据库的性能及完整应用验收未完成。按用户要求，继续不调查录音录屏性能。
