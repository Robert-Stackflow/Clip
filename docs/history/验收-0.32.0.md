# Clipper 0.32.0

本轮优化图片拖出、图片另存为、会话恢复和拖拽图标。继续使用 0.31 已校对的 One 组件与各页骨架；没有重新宣称本轮修改了全部 UI。

| 项目 | 实现与验证 |
| --- | --- |
| 图片拖出 | 已有合格小缩略图的记录复用缩略图，不再完整解码原图；首次物化保留 PNG/JPEG/DIB 等原始字节，每块最多解码 192 KiB；缺少合格缩略图的旧记录仍调用原图校验 |
| 图片缓存 | 只在私有缓存中写临时文件，最后提交后才返回路径；同时请求排队复用；容量按实际保留文件计入；变化、取消、退出和路径替换均检查，新增 DIB 和暂存文件清理 |
| 图片另存为 | 等待文件选择不占用操作队列；分块写临时文件、异步刷新后再提交；保留用户选择的文件名和已确认覆盖行为；写入时变化的目标或新出现文件保留并报错 |
| 有效性 | 图片保存及主窗口、拖放窗口、托盘拖出绑定记录哈希和会话；关闭窗口、删除/编辑、移出容器、锁定和切换资料时取消旧任务；操作已进入原生文件提交后不可撤回该次提交 |
| 会话恢复 | 每次激活资料初始化传输缓存；初始化并发合并，初始化中退出会丢弃过期缓存；恢复后图片可再次物化，旧工作不恢复 |
| 拖拽图标 | 两个维度同时限制，保留比例；私有窄长图样本由 64×11520 改为 1×64，避免放大为过高位图 |
| 构建 | Rust 编译限制两项并行，避免高并行冷构建在本机资源不足时无法启动编译进程；本机冷构建通过 |

原生文件提交调用 Koffi 的异步接口，由其工作线程执行；官方支持从 3.2 起在异步回调读取对应 GetLastError，本项目现有依赖为 3.3.2，没有升级依赖。见 [异步调用文档](https://koffi.dev/load#asynchronous-calls) 与 [版本记录](https://koffi.dev/changelog)。实际 Windows MoveFileEx 的拒绝覆盖、明确覆盖及原字节保留已在私有目录中执行，不以模拟提交替代。

私有合成 PNG 为 8763654 字节（约 8.36 MiB），1600×1600 像素，已保存小缩略图。重复拖出七次，旧版中位约 29.49 ms，新版 0.146 ms；旧版每次解码原图，新版零次，缓存命中不分配解码 Buffer。首次物化最大单个解码 Buffer 从整份 PNG 降至 192 KiB。

首次物化单次样本为 42.5→52.3 ms，定时器最大间隔为 29.3→16.2 ms；PNG 另存为单次样本为 13.5→155.9 ms。总完成时间没有改善，新的流程包含分块检查、刷新与原生原子提交；响应改善集中在避免同步解码、主线程提交和重复处理。不能将七个缓存样本或单次磁盘样本推断为所有实际场景的持续延迟或峰值内存。编码字符串、数据库读取和完整应用驻留未纳入本次内存计数。

测试使用实际 Electron nativeImage 和实际 Windows 文件提交，文件选择器与附件接口为 VM 适配器，WebContents.startDrag 为桩；没有发起真实 OLE 拖拽、显示桌面窗口或访问系统剪贴板。验证 PNG/JPEG 原始字节、JPEG 注释、原文件不变、取消保留原目标、写入中的目标变化、新文件竞争、受保护位置、关闭窗口、初始化并发和恢复。九项缓存与原生提交测试，以及三个实际主程序 IPC/会话适配测试新增到核心回归。

327 项逻辑测试通过；类型检查通过；语言绑定检查 142 文件、未绑定项为零。构建界面的 348 项布局、120 项 UI 和 16 项搜索检查重新执行，并与本机 One 0.16.2 实际源码进行明暗主题共 16 项基础组件样式比对，全部通过；来源摘要见 ONE-UI-REVIEW-0.32.json。未改动的媒体、通知和动效沿用 0.31 证据，不把旧报告计作本轮重测。打包后实际字体、加密恢复、文件同步、Rust 文档解析、重复堆栈、加密搜索及图片物化/保存复验另见交付报告。

没有新做物理桌面、系统剪贴板、双设备、麦克风、硬件录制、混合 DPI 或干净 Windows 验收。原生窗口边框和阴影沿用既有设置。没有签名或公开发布。原始项目、参考仓库和以前交付保持原样。
