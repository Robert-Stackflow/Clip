# 0.47.1 大型备份校验预览

文件选择按 256 KiB 分块计算指纹，避免在主进程分配整份备份。校验预览在单个短期线程中读取、解密、解析、验证 PNG 和试导入内存数据库；加密输入分块解密，原始明文快照通过一次转移交给主进程，成功试导入并等待线程退出后才允许恢复。PNG 解码器仅在出现图片时加载。

预览和取消不占用历史写入队列。重复预览等待旧线程退出；取消、过期、切换资料、锁定和退出使旧结果失效并清除快照。取消正在运行的原生解码时，先等待解码进程关闭，再结束线程。明文备份自动显示可取消的校验对话框，加密备份的校验阶段也允许取消；用户关闭对话框时，迟到结果不会重新显示。

## 功能与响应证据

- 462 项核心逻辑回归、TypeScript 检查和语言绑定检查通过。新增七组备份预览检查覆盖明文/加密、PNG、富文本/私有格式/附件、跨块 UTF-8、失败后旧快照失效、取消、替换、超时、缺失线程文件与文件容量保护。
- 隔离 Electron 窗口读取实际大型磁盘备份时，16 次快捷回复写入及随后状态查询都在预览尚未结束时完成，单次约 1–5 ms。明文与加密校验对话框取消检查通过；加密图片预览、正式合并和原始图片内容一致性通过。校验期间正常退出约 185 ms。
- 检查使用自有资料和合成内容，自动记录暂停；没有操作日常剪贴板，也没有重新调查录音录屏性能。

## 固定基线对照

基线是 Git `c149b34` 的备份管理与加解密实现。每种文件各做五轮交替独立 Node 22 进程，同一份 48 条大文字记录的 41.2 MiB 备份。新版使用实际生产构建的预览线程。测量包含文件指纹、读取、解密、解析、校验、SQLite 试导入和线程退出；不包含正式合并、界面绘制或 PNG 解码。下表为五轮中位数。

| 场景 | 预览耗时，旧 → 新 | 最长事件循环停顿，旧 → 新 | 主线程堆增长，旧 → 新 | Windows 进程峰值工作集，旧 → 新 |
| --- | --- | --- | --- | --- |
| 明文 | 1692 → 1610 ms | 1666 → 15 ms | 43.18 → 0.86 MiB | 259.7 → 311.5 MiB |
| 加密 | 1777 → 1693 ms | 1649 → 18 ms | 43.19 → 0.86 MiB | 260.1 → 273.3 MiB |

原始轮次及测量范围保存在 `work/current/backup-preview-performance/result.json`。Windows 峰值包含线程和进程启动，取消后的强制 GC 采样仅供诊断，不代表真实后台驻留。首轮加密候选有额外整文件复制导致约 395 MiB 峰值，已通过分块解密和一次转交消除；当前总峰值仍高于基线，不能把主线程堆下降称为整体内存优化完成。
