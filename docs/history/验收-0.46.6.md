# 0.46.6 大内容同步准备

## 改动

局域网拉取响应和主动推送共用发送准备：大于 64 KiB 的正文在最多两个短期工作线程中读取并编码，普通短文本保留即时路径。通过轻量摘要分流，无需先在主进程读取原件。线程读取只读 SQLite 快照，直接编码数据库中的正文 JSON，避免大 Base64 字符串的重复解析和序列化。字节数组移交后线程退出，发送完成或失败后清零。整个准备及传输阶段最多占用两个正文槽位，慢连接不能无限累积已准备的正文。没有增加依赖、数据库格式、协议版本或明文暂存文件。

发送前重新确认当前资料、同步代次、发布身份、哈希和共享状态。推送先核对 TLS 证书指纹，再确认发送资格，随后发送请求。撤销或关闭同步取消任务和连接。加密数据库的独立密钥副本在移交和使用后清零。旧协议版本筛选改用轻量格式摘要。

## 验证

新增 8 组回归使用真实读库工作线程，覆盖明文/加密历史、原始格式与目录附件逐字节、错误密钥、撤回/仅本机、协议版本、线程上限、超时/停止、准备后的隐私变更、短内容分流及传输槽位的占用与释放。文件数据库 TLS 回归实际拉取 10 MiB 附件、推送 2 MiB 附件，收到的原件与来源一致，准备字节在完成后清零；证书不匹配和发送资格失效时服务器没有收到 HTTP 请求。隔离资料不接触系统剪贴板、录制或输入注入。

完整核心 429 项、类型、双语覆盖及包内运行结果记录在交付校验报告中。下列测量对应最终直接编码方案，未使用早期重复序列化方案的结果。目录包的 Electron 44.5.1 / Node 24.21.0 实际运行新工作线程，读取加密 3 MiB 原始格式并验证编码一致，原数据库摘要未改变。

固定基线为 a271f3b（0.46.5），使用同一合成 10 MiB 附件与 SQLite，五轮交替、每轮独立进程，使用目录包的 Electron 在 Node 模式运行，当前方案加载包内工作线程。仅测读取加发送 JSON UTF-8 准备，正文一致性摘要相同：

| 中位指标 | 基线 | 当前 |
| --- | ---: | ---: |
| 主进程事件循环最大超时 | 47.72 ms | 12.84 ms |
| 完整准备耗时 | 50.62 ms | 106.13 ms |
| 主进程堆增长 | 53.40 MiB | 0.49 MiB |
| 准备时外部字节增长 | 13.33 MiB | 13.33 MiB |
| 进程采样峰值 RSS（含线程） | 122.41 MiB | 103.74 MiB |

工作线程提高了事件循环可响应性，直接编码减少了临时内存，但启动和退出线程仍增加约 56 ms 的完整准备耗时，因此小内容保留即时处理。峰值为定时采样及准备完成时的内存观测，可能遗漏很短的峰值；任务后 RSS 为基线 82.27 MiB、当前 90.46 MiB，不能宣称长期驻留内存降低。完整报告位于 work/current/sync-item-performance-electron/result.json。另有系统 Node 22 的五轮对照，结果保存在 work/current/sync-item-performance/result.json；两种运行时的结果不合并计算。

此测量没有 UI、TLS 传输、接收校验和写入耗时。TLS 回归为同一 Windows 主机的隔离实例，不能代替两台物理设备、防火墙或路由器验收。接收后的解析/校验/落库及文件发布最终提交仍需优化。
