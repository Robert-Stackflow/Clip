# 0.25 升级恢复点

实现升级前的数据留存、完整数据库校验及复制恢复。保留 One 风格的分类导航、列表、控件和双语布局。工作源码在 `work/next-0.25.0`，没有替换根目录的日常版本。

- 版本变化时先创建原格式恢复点，再打开、迁移和清理历史；同版本重启不重复创建，新资料不生成空恢复点。缺少已配置的数据库时拒绝创建空历史。
- SQLite 一致读事务保留已提交 WAL、全部表、索引、触发器和本机数据库配置。加密数据库及其密码/恢复密钥封装保持加密，不产生明文暂存数据库。恢复点不包含引用的源文件或数据库外的界面配置。
- 数据与备份新增「升级恢复点」分类，支持手动创建、校验预览、复制恢复及确认删除；启动恢复窗口可直接选用已有恢复点。自动升级与安装更新前的恢复点合计保留三份，手动恢复点不自动清理。
- 恢复创建独立目录并原子切换，保留原资料及恢复点；暂停记录、自动备份与同步，清除复制的同步身份。原来要求加密的资料不能恢复为明文：必须设置新密码并确认恢复密钥。
- SHA-256、资料编号、普通目录和固定文件列表检查阻止损坏、改变、链接及外来文件参与恢复或删除。过期、取消、改变的目标资料和锁定状态不能沿用预览。后台任务受时间和内存上限约束。
- 更新安装入口在辅助进程接管之前等待恢复点完成；创建失败不会进入安装。安装程序版本回退尚未实现。

隔离验证：286 项逻辑检查通过，包含原格式、清理前留存、WAL 并发写入、加密与原密钥恢复、保留与删除边界、校验后改变、取消和更新接管顺序；类型和 1976 处中英文绑定检查通过。现有页面 288 个布局场景、新恢复点 72 个布局与操作场景通过。Electron 44.5.1 隐藏窗口渲染通过。大数据验证使用 64 条合成记录，恢复点约 55 MiB，处理期间主事件循环仍可响应。

最终应用归档内的 55 个构建文件及三项解包原生程序与独立打包目录逐一校验通过。实际交付运行时加载归档内的 recovery-worker、加密 SQLite 和原生桥接依赖，完成明文手动恢复点、加密版本变化恢复点、原恢复密钥及独立加密副本恢复；原资料与恢复点继续保留。此项采用生产核心的测试导出，未启动完整应用主入口。开发目录与独立打包目录的差异仅为依赖路径、相应调试映射和 C# 编译信息，输入源码相同。

以上使用隔离资料、合成内容及模拟界面接口，没有访问用户历史、系统剪贴板或物理键鼠。原生锁定/休眠、完整跨应用、多屏与干净系统仍待实机验收。GitHub 正式发布的真实升级、安装签名和完整程序版本回退仍保留在开发计划；数据恢复点不等于这些工作已经完成。
