# Clipper 0.3 使用与验收记录

日期：2026-10-01。Windows 11 x64（10.0.26200），单显示器 150% 缩放；Electron 44.5.1、TypeScript 5.9.3、QuickJS Emscripten 0.32.0。

## 本版交付

在 v0.2 上增加文本工具：Ollama / LM Studio / 在线兼容接口、模型列表、翻译/总结/改写/自定义指令、结果预览与应用、OCR 文字转翻译、隔离 JavaScript 脚本、脚本备份，以及可选 URL 入口。界面沿用 One 的浅深主题，处理窗口左右对照输入和结果。

解压 ZIP 并运行 Clipper.exe，保留所有配套文件。源码发布目录为 release/0.3.0/win-unpacked。数据库仍使用 schema 2；原历史、富模板、分类和设置保持兼容。API 密钥与服务配置不进入历史备份，脚本需从文本工具单独导出。

七组发布 EXE 集成：tests/electron.cjs、integration.cjs、advanced-ui.cjs、capture.cjs、drag.cjs、text-tools-ui.cjs、text-tools-boundaries.cjs。日志保存在 work/packaged-0.3-*.log。测试使用隔离用户目录；剪贴板结束后恢复；测试服务器只接收预设内容，不连接付费服务。

针对新增功能还做了两项修复：取消外部确认时等待主进程消费请求，再检查下一项，避免取消后重复弹窗；脚本在启动完成前被取消时不再向已结束进程投递内容。输入与输出编辑在运行期间锁定，完成后再开放结果操作。

## 测试边界

- 本机没有运行 Ollama / LM Studio。AI 测试使用隔离的协议服务器，返回固定测试文字，未验证实际模型推理、翻译准确率、付费账号或各服务商参数差异。
- URL 的生产注册逻辑在测试中映射到唯一临时协议；Windows 负责实际注册与启动接收进程。Clipper 自身冷启动和运行中动作分别验收，没有占用真实 clipper-win 关联，也没有进行浏览器到正常用户资料目录的完整人工验收。
- OCR 使用本机已安装语言组件，个别英文字母会误识别；已验证识别文字原样进入翻译预览，未宣称 OCR 无误。
- 脚本引擎没有注册宿主接口，独立工作进程提供终止边界；这不等于操作系统级别的完备安全沙箱。脚本堆限制不包含 Electron 与 WebAssembly 自身开销。
- 沿用 v0.2 的兼容性边界：多屏混合缩放、Windows 10、干净机器、Office/Explorer/管理员应用、远程桌面及长期驻留仍需补充验证。
- 局域网同步、历史数据库加密、Windows Hello、存储迁移、定时备份、长截图、录屏和自动升级继续按后续阶段实施。

## 使用入口

1. 文本工具 → 添加服务，填写地址、模型及必要密钥；可查询模型列表。
2. 选择文字 → 翻译 / 总结 → 核对输入和接收地址 → 开始处理 → 复制、另存或替换。
3. 图片 → 识别文字 → 翻译文字，先校正 OCR 结果再发送。
4. 文本工具 → 新建脚本，填写 JavaScript 函数体；从文字详情运行并预览结果。
5. 文本工具 → 启用 URL 入口；外部新增或复制需在应用中确认。移动程序目录前先停用，在新位置重新启用。
