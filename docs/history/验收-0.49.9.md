# 0.49.9 JPEG 导入后台转换

JPEG 文件导入现在复用独立原生图片进程，将原图解码与 PNG 编码移出主进程。JPEG 转换和 PNG 缩略图共享单进程队列，最多四个等待任务，输入总量不超过 64 MiB；保留原有 16 MiB 内容、4,000 万像素和 16,384 边长限制，辅助进程仍有 384 MiB 限额与 15 秒期限。进程不接收文件路径，不产生图片临时文件，结束或失败后释放任务。

原 JPEG 仍作为 JFIF 原格式按字节保存，转换得到的 PNG 不要求压缩字节相同。导入的所有退出路径清理读取缓冲区；锁定、资料切换和退出取消旧导入，选文件后也复核窗口与任务代次。保存到拖放容器前复核资料身份。修正选择文件入口没有等待最终保存的问题，使保存失败可以正确返回给调用者。

## CMYK 与内容保持

上一轮原型将 CMYK 直接交给 WIC 通用颜色转换，出现最大通道差值 90。独立实现正常 CMYK 到 BGRA 的整数乘法与舍入转换，直接写入 WIC 请求的像素缓冲区，没有额外创建完整位图。计算依据对照了 [Skia 的 CMYK 转换](https://skia.googlesource.com/skia/+/refs/heads/main/src/codec/SkSwizzler.cpp) 与 [WIC 原生像素格式说明](https://learn.microsoft.com/en-us/windows/win32/wic/-wic-codec-native-pixel-formats)，最终以当前 Electron 的逐像素结果核对，不以源码相似度作为兼容证明。

正式 `incomingFiles` 和原解码路径比较，16 种 JPEG 全部像素一致，覆盖 RGB、灰度、渐进编码、普通 CMYK、变化黑色墨量、渐进 CMYK、sRGB ICC、改变主色参数的 ICC 与八种 EXIF 方向。加上透明 PNG，共 17 个解码样本；JPEG 导入主进程原图解码次数为零，原文件与原格式字节保持。方向样本保留原行为，不表示新增自动旋转。

另保留六个旧路径已有失败的 BMP/GIF/WebP 样本：两版在当前 Electron 下均拒绝解码。这是未修复的格式支持问题，不能把 23 个检查全部写成成功导入，也没有删除失败样本来缩小范围。首个正式矩阵检查因此失败，随后明确比较旧路径原有的成功或拒绝行为，而未放宽生产内容校验。

核心回归 505 项通过；之后新增两项 JPEG/PNG 共用队列、输入边界、损坏输入、活动与等待任务取消、原缓冲区保持检查，缩略图套件合计 5 项通过。类型与 2,250 条源语言字符串检查通过。没有重复已经验收的肤色选择器间距，也没有调查录音录屏性能。

## 转换阶段测量

两种 JPEG 各三轮交替独立 Electron 进程，旧读取函数固定为 b9c63d1，候选使用正式导入函数与共享队列。12 个样本含文件读取、内容验证、原格式保留和缩略图，未包含数据库保存或桌面输入。

| 中位数 | 3,840 万像素大图旧版→新版 | 256 万像素噪点旧版→新版 |
| --- | --- | --- |
| 导入转换总时间 | 325.3→562.5 ms | 321.9→418.3 ms |
| 最大计时器间隔 | 257.4→16.4 ms | 231.7→61.8 ms |
| 主进程 Windows 峰值工作集 | 261.8→113.9 MiB | 171.6→165.0 MiB |
| 父/辅助进程峰值之和上界 | 271.0→124.3 MiB | 193.5→192.1 MiB |

响应改善伴随总等待增加；独立读取的进程峰值之和不是同时发生的全应用峰值。未强制 GC 或调整工作集，不将这些数值当作长期驻留或全面内存改善。

## 正式目录包导入、保存与索引

0.49.8 与 0.49.9 各三轮交替启动真实目录包，使用暂停自动记录的独立资料和隐藏的受信任主界面。文件选择对话框返回自建图片路径，其后调用正式 `addFiles` IPC、转换、缩略图、保存、索引、加入拖放容器和通知；同时从实际渲染器调用 `updateState`，测量请求等待。版本从 `app.getVersion` 核对，记录和容器数量、原格式 SHA-256、缩略图及源文件保持全部通过。

| 中位数 | 大图旧版→新版 | 噪点旧版→新版 |
| --- | --- | --- |
| 完整导入等待 | 366.9→610.7 ms | 802.5→906.8 ms |
| 最大界面 IPC 请求等待 | 254.8→23.0 ms | 437.2→484.1 ms |
| 主进程最大 5 ms 计时器间隔 | 265.2→19.4 ms | 451.2→478.2 ms |

新版大图首轮 IPC 等待 57.1 ms，其余两轮 22.6/23.0 ms，全部保留。新版噪点 IPC 等待 454.9–510.5 ms，比旧版 434.6–445.2 ms 更差；最终保存与索引仍阻塞主进程。不能声称所有图片导入已流畅。

100 ms 全进程树采样的阶段峰值增量中位数，大图 165.6→25.6 MiB，噪点 49.0→209.4 MiB。每个进程先导入大图再导入噪点，两版进入第二项前的驻留不同，因此这些增量不足以公平比较噪点绝对峰值，且可能漏掉短峰值。新版高样本明确保留，未把转换阶段的低峰值推广为完整应用的峰值改善。以后测量同时记录绝对起点与峰值；这批有效样本未因增加字段而重跑替换。

真实加密资料在辅助解码进程活动期间，通过正式 IPC 锁定；导入拒绝并只显示解锁页。独立追加的锁定检查在进程退出后，以只读数据库核对主记录和列表索引仍各两项，没有迟到的第三项写入。第一次启动测量误将 `ELECTRON_RUN_AS_NODE` 设为空字符串，生成程序未能启动；已改为删除变量后运行。测试不控制物理鼠标、键盘或用户其他程序，不覆盖窗口所有权/失焦守卫；隐藏界面流程不能替代前台实际拖放验收。
