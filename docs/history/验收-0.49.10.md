# 0.49.10 手动大内容后台保存与容器事务

手动添加和拖入的大内容现在复用 CaptureWriter。最终内容校验、摘要计算、序列化、SQLite 记录和索引写入、加入拖放容器均在短期后台线程中完成；线程只返回预览、容器 ID 和精简变更通知。小内容仍使用原有同步路径，阈值沿用自动捕获按字符串长度的判断，没有新增全量正文常驻缓存。

后台事务内重新读取容器并检查 200 项限制。记录、索引和容器一起提交或回滚；重复内容保留 ID、来源、创建时间、收藏、置顶、标签与隐私。同步账本观察在同一后台事务中执行，网页共享收到不带正文的变更通知，主进程只更新已提交的容器 ID 并刷新界面。没有改变手动导入自动共享的规则。

取消在提交决定之前终止并回滚；决定之后等待事务结束，避免在已接受提交时强制终止线程。返回前继续检查资料身份，锁定或资料切换后的结果不更新旧界面。既有停止流程等待线程退出与连接释放。

## 验证

512 项核心回归通过，新增四项后台写入检查和一项实际主进程 IPC 检查：明文/加密原内容、重复记录与隐私、容器容量变化、容器 SQL 写入失败、记录、预览和列表索引回滚、取消和再次使用、提交已被接受时等待、资料失效后不写入。提交决定测试使用带受控延迟的真实 SQLite 事务，独立验证协调协议。类型及 2,252 条源语言字符串检查通过。

初次核心回归为 509/510，语言入口测试将新增写入器依赖错误替换为 Dummy 类；补齐真实依赖后，新增大内容入口测试又发现网页共享测试对象缺少 reconcile 回调。两处测试环境补齐后，完整 512 项通过，没有删除断言或放宽生产守卫。未重复 JPEG 色彩矩阵或已完成的界面间距调整；录音录屏性能继续排除。

## 实际目录包导入

0.49.9 与 0.49.10 各三轮交替启动独立真实目录包，每个程序依次导入自建 8,000×4,800 纯色 JPEG 和 1,600×1,600 噪点 JPEG，共 12 个样本。暂停自动记录，隐藏测试自己创建的可信主窗口，以自建路径替代文件选择结果，其后通过正式 addFiles IPC 执行图片转换、缩略图、保存、索引、容器变更和通知。实际渲染器并行调用 updateState 测量等待，原文件及 JFIF 原格式的 SHA-256、缩略图、记录和容器数量均核对。

内存明确变差：噪点旧版绝对峰值 446.0–687.9 MiB，新版 635.3–688.0 MiB，所有有效高样本完整保留。100 ms 进程树采样可能漏掉短峰值；每轮先导入大图再导入噪点，并在两项之间核对原始正文，二次导入起点受前项驻留影响。此次同时保留绝对起点、绝对峰值和增量，新版一项大图增量为零只表示采样期间没有超过起点，不表示没有分配内存。没有强制 GC 或工作集调整，不将线程退出等同于全应用内存目标已完成。

比较过程在 JPEG 转换期间锁定的检查通过。另启动一次新版程序，在真实后台保存线程活动期间通过正式 IPC 锁定历史；导入拒绝且仅显示解锁页。关闭程序后解锁自建加密资料，以只读连接核对主记录与列表索引仍各两项，没有迟到的第三条记录或列表索引写入。线程创建的观察包装仅记录活动状态，不替换提交、有效性检查或取消守卫。

测试没有操作物理鼠标、键盘、系统剪贴板或用户其他程序；隐藏窗口 IPC 不是前台实际拖放、长期驻留或连续同步的完整验收。
