# Clipper 0.2 使用与验收记录

日期：2026-10-01。环境：Windows 11 x64（10.0.26200）、Electron 44.5.1、Node.js 22.16.0，当前单显示器缩放 150%。

## 交付内容

在 v0.1 剪贴板核心上，增加图片/文件快捷回复、模板变量、自定义分类、批量操作、拖拽容器、原生文件/图片拖出、图片另存、Windows 本地 OCR、区域与整屏截图。保持 One 的浅深主题、原生标题按钮和 main/preload/renderer 分层。

打开源码目录的 release/0.2.0/win-unpacked/Clipper.exe，或解压发布 ZIP 后打开 Clipper.exe；保留全部配套文件。升级前可先用旧版导出备份。数据库升级到 schema 2，兼容原文字模板；新版备份包含富模板与分类，仍能导入 v1 备份。旧版不能读取升级后的数据库。

五组发布包集成脚本：tests/electron.cjs、tests/integration.cjs、tests/advanced-ui.cjs、tests/capture.cjs、tests/drag.cjs。日志保存在 work/packaged-0.2-*.log，全部直接针对发布的 Clipper.exe 执行。

数据库测试包含 v1 模板迁移、未来 schema 拒绝降级、旧记录真实存储字节计量、批量事务回滚、容器保留保护、富模板/分类备份去重、导入回滚、不同缩放的坐标换算，以及变量名与对象属性重名的情况。

截图验收使用纯色测试窗口覆盖屏幕，核对画面与裁剪位置。系统捕获返回 2561×1601 PNG；全屏选区窗口内容范围为 1707×1067，选区依实际图像比例计算边界并取整，输出与预期一致。修正了最初选区窗口未铺满显示器的问题。颜色允许小幅系统色彩转换差异，不作 HDR 精度承诺。

OCR 测试使用本机已安装的简体中文语言包，实际识别了英文句子。个别粗体字母存在误识别；界面允许编辑，识别结果经用户保存后才加入历史。

原生输入验收先真实点击测试目标文本框，再从 Clipper 发出粘贴；仅调用浏览器测试工具的点击会出现网页有焦点但系统键盘未进入文本框的情况。拖放验收使用系统鼠标输入，验证接收端读到的文件名、长度与文字内容，并确认源文件内容未变。

测试使用独立资料目录；剪贴板原内容先物化为可回写的 ClipboardItem，结束后恢复。测试文件选择框使用隔离路径返回值，未自动操作系统文件对话框。

## 当前边界

- 只实测当前单屏 Windows 11 x64。多屏混合缩放、Windows 10、干净机器、Office/Explorer 的具体接收行为、管理员窗口和远程桌面仍需兼容验证。
- 原生拖出按复制/链接语义提供数据，原文件不移动；图片临时 PNG 退出后清理。文件模板和文件历史不备份文件本体。
- 当前 OCR 依赖 Windows 语言组件；识别质量不保证。无语言包会提示，不自动安装或联网。
- 截图基于冻结画面，暂不包含长截图、录屏、标注编辑与跨屏拼接。
- 尚未完成数日驻留、满容量历史、锁屏/休眠循环的压力测试；未提供安装器、代码签名和自动更新。
- AI、脚本、局域网同步、加密、录制等仍属于后续阶段，本版没有将其标记为已实现。

## 使用入口

- 图片或文件预览中的“保存为快捷回复”：保留原内容作为模板。
- 文字模板中的 {{姓名}}：使用时填写；{{日期}} / {{时间}} 按本地时间生成。
- 侧栏自定义分类的 +：设置同时满足的类型、正文、来源和标签条件。
- 列表顶部勾选按钮：批量收藏、标签、入栈、移入/移出容器、删除。
- 拖拽容器：拖入本地文件，或拖动记录到其他应用。
- 图片预览中的识别按钮：本地 OCR；下载图标：另存 PNG。
- 顶部“截图”：选择显示器和模式，区域模式 Enter 保存、Esc 取消。
