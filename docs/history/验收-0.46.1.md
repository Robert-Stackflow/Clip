## 自动清理

每次剪贴板写入和立即保存设置都会调用自动清理。之前会读取完整列表，将所有缩略图和摘要解析进 JS，再判断过期和数量限制。

新增可重建的保留摘要索引，只存储更新时间和保护标记。清理在 SQL 中排序、过滤并返回待删除 ID，保留收藏、置顶、共享、堆栈重复副本及容器内容。删除使用独立保存点，失败时全部回滚，并保留外部事务和既有撤销快照。普通历史清空也使用 ID 查询，撤销仍保留完整附件内容。

主记录、备份格式及数据库版本 7 不变；加密索引随数据库加密。验证了旧库补建、旧写入兼容、更新时间更新、移出保护集合、同时间排序、失败回滚及孤立缓存排除。

## 性能测量

基线为 `8692923` 的实际 Store 和摘要索引。6 个隔离 Node/SQLite 进程，3 轮交替执行，每进程同样的 10,000 条合成历史，含 5,000 张有效 PNG，7 次无删除自动清理；每次测量前显式 GC。另测一次将数量限制降至 50 的立即设置清理，各次结果都保留相同的 320 条记录（50 条普通记录及所有保护记录）。

| 指标 | 基线各轮中位 | 本版各轮中位 |
| --- | --- | --- |
| 无删除清理耗时 | 248.61 / 259.08 / 231.75 ms | 15.62 / 15.56 / 15.99 ms |
| 事件循环定时器延迟 | 248.78 / 259.23 / 231.87 ms | 15.71 / 15.78 / 16.10 ms |
| 方法返回时采样 JS 堆增量 | 约 220.74 MiB | 约 16.70 KiB |
| 降低数量限制并实际删除耗时 | 1206.70 / 900.90 / 886.98 ms | 505.26 / 492.53 / 667.11 ms |

这是指定合成历史下的自动清理开销，不是应用总内存、连续采样峰值或真实剪贴板吞吐测试。大量实际删除仍同步执行，不能表述为完全不阻塞。数据库预载使用生产 Store.save，测试结束清除样本；不会创建额外源码或运行目录副本。
