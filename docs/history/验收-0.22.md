# Clipper 0.22 安装器验收

2026-10-01。交付独立设计、实际可运行的 Windows 图形安装器，应用版本为 0.22.0。双语应用功能沿用已完成的 0.21 范围，本版集中处理安装与分发。

## 已完成

- One 风格的自定义窗口：留白、灰色辅助区、深色主按钮、卡片插画、欢迎页、安装状态、完成页、错误和重试。安装器中英文可即时切换。
- 仅为当前用户安装到 `%LOCALAPPDATA%/Programs/Clipper`，开始菜单、Windows 应用卸载入口；不请求管理员权限。安装完成后由用户选择启动或结束。
- 离线嵌入 NSIS 引擎，启动前校验 SHA-256，安装后检查实际应用 asar。准备文件时显示真实字节百分比，校验和安装时显示活动状态。
- 旧版正在运行时停止，提示从托盘正常退出，不结束进程。检查空间、安装版本；拒绝覆盖已安装的更新版本。
- 覆盖安装前保留旧程序与安装入口，调用旧版正常卸载流程保留用户资料，再安装新版。引擎失败后恢复旧程序、安装注册和开始菜单；恢复自身失败时保留程序副本并在日志中记录位置。应用从未在替换过程中自动启动，故不会在这一步迁移历史格式。
- 在安装磁盘的独立随机临时目录工作，完成后清理自身临时文件。取消只允许在准备及备份阶段；实际替换开始后等待结束。

## 实际证据

`tests/custom-installer.cjs` 使用独立 NSIS 身份、隔离的中文与空格目录，以及独立资料哨兵文件。实际编译同一前端、嵌入实际 NSIS 引擎，并完成：

1. 独立程序运行时返回 1602，未结束该进程或创建安装文件。
2. 首次安装、应用 asar 校验、开始菜单和卸载注册通过。
3. 修改该测试身份的版本记录后返回 1638，未改动应用文件。
4. 实际移除旧程序后注入安装失败，恢复旧程序、注册、开始菜单，资料哈希不变。
5. 再次安装及卸载通过，注册与快捷方式清理，资料哈希不变，自身临时目录清理。

Windows 系统临时盘为 C，测试安装盘为 D；前端给引擎使用安装盘临时目录。较深的测试目录在早期覆盖试验中暴露了 NSIS 替换旧文件失败的问题，最终采用独立程序备份、正常卸载与失败恢复的替换流程。上述通过结果来自最终流程，未把失败轮次算作通过。

实际 WPF 后台渲染中文/英文的欢迎、准备、完成、运行中提示四种页面，分别生成 100%、150%、200% 图像；检查语言切换、安装时按钮限制、真实准备百分比、引擎阶段不可取消和完成动作。没有显示桌面窗口、使用键鼠或访问剪贴板。

`--verify-payload` 校验实际发布前端中的引擎、字节进度与安装前取消。原始 NSIS 包内的应用 exe、asar、两个原生助手和 SQLite 预构建模块与构建目录一致。应用 250 项逻辑检查已通过，53 个构建文件和 SQLite / 原生桥接的真实发布运行时检查通过。

## 范围与限制

本次交付没有代码签名，Windows 可能显示未知发布者提示。干净 Windows 10/11 机器、实际多显示器切换和完整物理桌面兼容性仍需要独立实机验收；后台渲染不替代这些检查。

GitHub 更新目标为 `Robert-Stackflow/Clipper`，联网更新和跨版本历史格式回退未在本次交付中启用。已有目录版开机启动项如指向旧位置，安装后需在应用设置中关闭再开启。卸载前可在应用设置关闭开机启动。

默认应用资料及安装目录外的自定义资料保留。不要将自定义资料目录放进程序安装目录；卸载会删除程序目录的内容。目录包仍可独立使用。0.21 的已验收双语交付保持不变。
