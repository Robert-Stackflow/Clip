# Clipper 0.18 验收

2026-10-01。Windows x64 目录包，未签名。参考 OneClip 公开功能与本地 One 设计；本次实现虚拟文件夹，不代表全部平台能力与实际应用兼容性已完成。

## 本次交付

- OLE Unicode/ANSI 描述的层级附件、空目录、零字节文件、隐式父目录；HGLOBAL/IStream/IStorage 保留原始内容索引，目录不读取 FileContents。
- 相对路径搜索与详情、目录/文件区分、根项目复制及真实拖出、子目录另存、模板与密码备份恢复。
- schema/备份 6、平面附件数据与哈希兼容、旧备份导入；旧程序拒绝新库。文字/图片同步协议继续为 4。
- 整组路径/层级/容量校验，目录链接与设备属性拒绝；专用缓存递归清理、占用重试，另存不覆盖已有目标。
- 修复未加密历史休眠恢复后，旧另存窗口仍可提交的问题：系统事件使原会话失效，恢复后也不会重新授权旧操作。

## 调试记录

开发态目录复制和另存先通过。初次桌面专项期间发现日常 0.17 仍驻留并占用热键；在用户从托盘退出后继续，后续测试会先检查日常实例。日常历史未自动删除或修改；首轮测试期间它可能记录了测试剪贴板内容。

初始拖放接收页使用 data: URL，目录读取出现 EncodingError。改为本机 HTTP 页面后，在产品代码未修改的情况下，目录层级和全部文件字节通过。另一个路径检查失败来自测试桥接直接传入 FileList；改为显式 File 数组后通过。中间用于诊断的原生接收窗口未收到拖放，不作为通过证据，相关记录保留；最终使用确实收到真实 OLE 拖放并递归读取成功的 HTTP 接收页。

休眠恢复用例先复现旧另存可提交，再增加会话代次失效处理；相同用例通过。开发失败日志保存在 work/folders-ui-*-0.18.log、work/folders-boundaries-suspend-regression-0.18.log；源码交付不包含测试数据和 work 目录。

## 限制

仅保留来源已经枚举并提供的成员；不会扫描磁盘、解析任意 Shell 命名空间或补齐来源未提供的文件。受控真实 OLE 样本不能证明 Outlook、Office、Explorer 或所有私有来源格式兼容。IStorage 容器布局可能改变，测试验证其内容和类标识，不声称逐字节保留原容器布局。

目录节点合计最多 256、16 层、相对路径 259 个 UTF-16 单元、原始内容合计 12 MiB，仍受单条和全历史容量限制。目录不参与内部元数据读取；文件/目录不参加局域网同步或网页共享。

复制/拖出生成未加密临时树，锁定/退出清理；被外部程序占用时需要释放后重试。主动另存目录由用户管理；强制中断导出可能留下同级 .Clipper-folder-*.part 暂存目录。源时间保留，属性不用于创建链接、只读或隐藏对象。

锁定/休眠自动化通过受控系统事件检查生命周期，不能替代物理休眠和真人解锁。签名安装、更新回退、中英界面、托盘最近项目与预览、字体/紧凑布局及实际设备验证继续列在开发计划中。
